# セキュリティ・機密情報

目的: 秘密情報の管理、扱うデータの取り扱い、アプリケーションのセキュリティ、AIエージェントの権限管理を定める。

## 秘密情報の管理

秘密情報 = APIキー、パスワード、アクセストークン、DB接続文字列、証明書・秘密鍵、クラウドの認証情報、ロボット・センサー機器の接続認証情報など。

- 秘密情報はコードに直接書かず、環境変数から読み込む
- ローカル開発では `.env` に記載する。`.env` はGit管理対象外とし、必要な変数名とダミー値を `.env.example` に記載して共有する
- 本番・検証環境ではクラウドのシークレット管理サービス（例: Secret Manager / Key Vault 等。インフラは AWS（サーバーレス）に確定した。現時点で、アプリが保持する秘密情報はない: Lambda の環境変数は、ID・テーブル名のみで、パスワードは Cognito が持つ。実ファイルサーバーの認証情報などは、**パラメータストア（SecureString。標準）**に保管する（`SecretPort` は、#206 で実装。環境ごとのパス `/sfm/<環境>/<種類>/<名前>` の下だけ。API の Lambda は読み取りと書き込み、ジョブの Lambda は読み取りだけ。参照名は、小文字・数字・`.`・`_`・`-` の 1〜4 階層に限り、`..` などで、ほかのパスを指せない。値は、ログ・エラー・画面に出さず、状態〔設定済みか・更新日時〕だけを返す）（決定。[ADR-0016](../10_design/adr/0016-ingestion-federation-rules.md)）。認証情報は、管理者が、画面から**書き込み専用**で登録し（#207）、保存後は再表示しない。値は、画面・API の応答・ログ・エラー・変更履歴に出さない（リクエストの本文は、ログに出さない。保管先のエラーの内容・原因も、値を含みうるため、引き継がない。変更履歴には、「認証情報を更新した」という事実と認証方式だけを残す）。書き込み権限は、専用のパスに限り、読み取りと書き込みの権限を分ける（ジョブは、読み取りだけ）。実装済み: #206・#207）を使い、`.env` ファイルを配置しない
- 環境（開発・検証・本番）ごとに異なる認証情報を使い、使い回さない
- 権限は必要最小限とする（最小権限の原則）。読み取り専用で足りる場合は書き込み権限を付けない
- 秘密情報をチャット・メール・Issue・PR・ドキュメントに貼り付けて共有しない
- 秘密情報を誤ってコミット・公開した場合は、履歴から消すだけでなく **直ちに該当の認証情報を無効化・再発行** し、関係者に報告する
- `.gitignore` に以下を含める
  - `.env`, `.env.*`（`.env.example` は除く）
  - `*.pem`, `*.key`, `*.p12` などの鍵・証明書ファイル
  - 認証情報ファイル（例: クラウドのサービスアカウントキー `*credentials*.json`）
  - ログ・ダンプ・実データのエクスポートファイル

## 扱うデータと取り扱い

| 区分 | 例 | 取り扱い |
|------|----|----------|
| 圃場・ハウスの運用データ | センサー値、ロボット稼働ログ、栽培・収量データ、ハウスの位置情報 | 協力農家・関係機関の機密情報として扱う。許可なく外部に公開・共有しない |
| 研究・評価データ | 第三者評価の結果、評価用データセット | 公開範囲は関係者の合意に従う |

- 実データ（本番・圃場由来のデータ）をリポジトリにコミットしない。テスト・サンプルには匿名化したデータか合成データを使う
- ログに個人情報・秘密情報・リクエスト本文全体を出力しない。必要な場合はマスキングする
- 外部サービス（生成AI・翻訳・オンラインツール等）に実データ・個人情報・秘密情報を入力しない

## アプリケーションのセキュリティ

- 通信は HTTPS / TLS で暗号化する。ロボット・センサーとサーバ間の通信も同様に暗号化・認証を行う
- 全てのAPIに認証・認可を設け、ユーザーの役割に応じて操作できる範囲を制限する。特にロボットやハウス設備の **遠隔操作・設定変更は、権限を持つ人だけが実行できる** ようにし、操作履歴を残す
- **ファイルサーバー（HTTP）の接続先**（[ADR-0022](../10_design/adr/0022-file-server-http-connection-provisional.md)。Issue #172）は、管理者が画面から設定できるため、SSRF（Lambda から、意図しない宛先へリクエストを送らせる攻撃）を防ぐ。内部のアドレス（ループバック・プライベート・リンクローカル。AWS のメタデータの `169.254.169.254` を含む）と、内部の名前（`localhost`・`*.internal` など）は、拒否する。保存のときと、接続の直前（名前の解決の結果のすべての IP アドレス）に、検査する。リダイレクトには従わない。判定できない値は、拒否する。`HTTP_FILE_SOURCE_ALLOW_PRIVATE` は、ローカル・E2E・テストだけで使い、`APP_MODE=production` では無効。認証情報の値（パスワード・トークン・API キー）は、設定・変更履歴・ログ・画面・エラーに出さず、秘密情報の保管先（SecretPort）に置く。接続テストの失敗は、理由だけを固定の文言で示す（接続先・ファイルパス・ネットワークのエラーの詳細は、出さない）。平文の HTTP は、許可し、画面で警告する
- **農業情報基盤の接続先**（[ADR-0024](../10_design/adr/0024-agri-platform-federation-ngsi-ld.md)。Issue #177）も、管理者が設定できるため、ファイルサーバーと同じ SSRF の対策（内部のアドレスへの接続の拒否・名前の解決の検査・リダイレクトに従わない・接続先を、画面・ログ・エラーに出さない〔書き込み専用。`SecretPort`〕）を守る。**農業情報基盤には、認証がなく、インターネットに公開されている**（ユーザーの判断。2026-11-13）。連携したデータ（運用データ。NFR-5.5）は、誰でも読め、書き換えられるため、基盤に認証が入ったときに、アダプタへ認証ヘッダーを足す。送らないもの: 手動入力の備考・入力者、ユーザー・設定のデータ。連携先の設定の画面・API は、取り込み設定と同じ権限（取得 `ingestion:read`・更新 `ingestion:configure`・接続の確認 `ingestion:run`）で、**接続先は書き込み専用**（応答・変更履歴・ログ・エラーに出さない）
- 外部入力（API・画面・センサーからのデータ）は必ず検証し、SQLインジェクション・XSS等を防ぐ（クエリはプレースホルダを使い、文字列結合で組み立てない）
- エラーメッセージに内部情報（スタックトレース、パス、SQL、設定値）を含めない
- 依存パッケージは信頼できるものを選び、脆弱性は、GitHub の Dependabot alerts（自動の検知・通知）で確認する（`npm audit` は、補助。自動更新 PR と、CI での audit は、使わない。決定。[ADR-0021](../10_design/adr/0021-nonfunctional-ops-doc-rules.md)）。リポジトリは公開のため、シークレットスキャン・プッシュ保護を有効にする（無料。ユーザーが設定。#249）
- 合成データを生成する Lambda（Issue #77。ADR-0012）の IAM は、**ファイルサーバーのモックの S3 の取り込み元の下（`robot/*`・`environment-sensor/*`）への書き込み（`s3:PutObject`）だけ**（読み取り・削除・DynamoDB・Cognito の権限はない）。環境変数は、バケット名だけ。置くのは、合成データだけ（実データ・個人情報は置かない）
- デモデータのコマンド（`pnpm demo-data reset`。ADR-0012）は、**データを消す**。公開の URL・Lambda からは、呼べない（運用者が、AWS のプロファイルを指定して、手元で実行する）。`--yes` がなければ、何も消さない。消すのは、ユーザー・ログインの試行回数の記録・ジョブのロック以外で、Cognito のユーザーは、触らない。AWS のエラーは、名前だけを出力する
- ファイルサーバーのモックの S3 のバケット（Issue #77。ADR-0012）は、非公開（公開のブロックをすべて有効）・暗号化・SSL を強制し、評価環境と一緒に削除する。ファイルは 3 日で自動で消える。**置くのは、合成データだけ**（実データ・個人情報は置かない）。API・ジョブの Lambda は、このバケットの読み取りだけ（`s3:ListBucket`・`s3:GetObject`）ができる。書き込み・削除の権限は、付けない
- ジョブの Lambda（EventBridge から起動。公開の URL を持たない。ADR-0011）の IAM は、DynamoDB の 2 テーブルへの必要な操作だけ（Cognito の権限は、付けない）。入力（`jobId`）は検証し、想定外の入力は、内容を出さずに拒否する。環境変数に、秘密情報を持たない
- 開発用 API（全データの消去・時計の操作・ジョブの強制実行）は、環境変数 `DEV_API_ENABLED=true` と明示したときだけ有効にする（既定は無効）。本番（`APP_MODE=production`）は、DynamoDB が必須で、`DEV_API_ENABLED=true` は設定エラー。Lambda では、指定にかかわらず無効。E2E・負荷テストの設定でのみ、明示的に有効にする
- Lambda では、`APP_MODE`・`PERSISTENCE` を必ず明示する（既定の `local`・メモリで動かさない）
- ログインの試行回数の制限（接続元ごと）の回数・時間は、既定で、失敗 5 回 / 15 分。環境変数（`LOGIN_FAILURE_LIMIT`: 1〜100、`LOGIN_FAILURE_WINDOW_MINUTES`: 1〜1440）で変えられる（誤ってロックされる事例が出たとき、コードを変えずに調整するため。大きくするほど、総当たりに弱くなるため、範囲を限る）。アカウント単位のロックは、アプリでは持たず、Cognito のユーザーごとのロックに任せる（嫌がらせで本人を締め出されないため。[ADR-0020](../10_design/adr/0020-authentication-rules.md)）
- ログインの試行回数の制限の接続元は、クライアントが付ける `X-Forwarded-For` を信頼しない。信頼するプロキシの段数（`TRUSTED_PROXY_HOPS`）を設定したときだけ、末尾から数えた値を使う。評価環境（CloudFront → 関数の URL）は、関数の URL が `X-Forwarded-For` を最初の 1 つ（クライアントが付けられる値）に切り詰めるため、段数では識別できない。CloudFront の Function が、利用者の IP を、ヘッダー `x-sfm-viewer-ip` に上書きで入れ、Lambda が、設定 `CLIENT_IP_HEADER` で読む（IP として正しい値だけ使う。ADR-0010）。関数の URL を、直接呼ぶ場合は、このヘッダーを、クライアントが偽装でき、この制限を回避できる（ADR-0006・ADR-0010）。認証のログには、接続元の IP が出る（`clientKey`。ログの保持は 1 か月）
- **関数の URL の直接の呼び出しを拒否する**（Issue #102。ADR-0010 の追記）: CloudFront が、API のオリジンへの呼び出しに、秘密のヘッダーを付け、API の Lambda が、値が一致しない呼び出しを、すべて 403 で拒否する。秘密の値は、Secrets Manager に自動生成し、**Lambda の環境変数には持たない**（環境変数は、秘密の ARN だけ。Lambda が、コールドスタートで、読む。IAM は、この秘密の読み取りだけ）。リポジトリ・ログ・応答・エラーに、値を含めない
- **アクセス制御の方針**（[ADR-0013](../10_design/adr/0013-environments-and-access-control.md)。Issue #78）: ログインは必須（公開しているのは、ヘルスチェックとログインだけ）。多要素認証は、設けない。**接続元 IP による制限・WAF は、設けない**（10 人程度の登録ユーザーが、インターネットから使う）。ロールは、管理者・一般の 2 種類（管理者は、すべての操作。一般は、割り当てられた設備の閲覧・手動入力・自身のユーザー情報の編集）。初期ユーザーは、管理者。ロールの分割は、実装済み（Issue #115。既存のユーザーは、`pnpm migrate-user-roles` で移す。operations.md 8.7）。**設備の割り当ては、ハウス側から行い、実装済み**（Issue #330。管理者は権限 `equipment:view-all` で全設備、一般は割り当てたハウスと配下だけ。範囲外は、存在しないもの〔404〕。閲覧範囲は、リクエストごとに判定する）。**通知も、閲覧できるハウスの通知だけを、表示・配信する**（Issue #331。ハウスに属さない通知は、管理者のみ。範囲外は 404。Web Push の宛先も、通知のハウスを閲覧できる利用者の購読だけ）。**取り込み・連携のログも、閲覧できるハウスの分だけを見せる**（Issue #332。ハウス別の API・画面。日時・ハウス・取り込み元・結果・件数だけで、接続先・認証情報・失敗の理由・全体の件数・連携キューの件数は、見せない。ハウスに結びつけられない結果は、管理者のみ）。取り込みの設定・全体のログ・連携のログは、管理者のみ（権限 `ingestion:read`）
- **環境ごとのデータ**: 開発サイトは、**基本は合成データ**。実際のロボット・センサーとの結合確認では、実データを取り込むことがある（**個人情報は不可**。条件は、結合確認の前に決める。ADR-0013 の 6）。本番サイトは、実データ可（**個人情報は不可**）で、扱う条件は、実証実験の前に決める（Issue #117）。どちらも、リポジトリ・ログ・コミット・Issue・PR に、実データ・個人情報・秘密情報を入れない。本番サイトの Environment は、デプロイできるブランチを `main` だけにし、承認者による承認を必須にする（Issue #117。承認者は T-Ishikawa-R のみ）。本番サイトには、合成データを生成する Lambda を作らず、`pnpm demo-data` も実行できない（安全装置）。開発サイトの結合確認の接続のアダプタ（HTTP）は、Issue #119 で実装した
- 認証に Cognito を使うとき（`AUTH_PROVIDER=cognito`。[ADR-0008](../10_design/adr/0008-cognito-authentication.md)）: パスワードは Cognito が持ち、アプリ（DynamoDB）は持たない。API が、サーバー側（IAM の権限）で Cognito を呼び、アクセストークンは、リクエストごとに Cognito で検証する（ログアウト・パスワードの再設定・ユーザーの削除が、すぐ効く）。アプリクライアントは、シークレットなしで、ブラウザには出ない。ログインの試行回数の制限（接続元ごと）は、DynamoDB で持つ（接続元は、ハッシュで保存）。Lambda は、環境変数の初期ユーザー（`INITIAL_USER_*`）を読まない。最初のユーザーは、手元で 1 回だけ、`pnpm initial-user` で作る（パスワードは、実行時の環境変数で渡し、保存・出力しない。AWS のエラーは、名前だけを出力する）
- ユーザーを削除したときは、そのユーザーのセッションと Web Push の購読も削除する。パスワードを再設定したときは、セッションを失効する。管理者が決めた（登録・再設定の）パスワードは、一時のもので、本人が最初のログインで変更するまで、ほかの操作を拒否する（決定。[ADR-0020](../10_design/adr/0020-authentication-rules.md)。パスワードの変更とログアウト以外の API は、403 `PASSWORD_CHANGE_REQUIRED`）。本人によるパスワードの変更（`POST /auth/password`）は、現在のパスワードの入力を求め、誤りは、ログインの失敗と同じく、接続元ごとの制限に数える（パスワードの総当たりの経路にしない）。変更すると、すべてのセッションを失効する。変更の履歴には、パスワード・ハッシュを残さない。ユーザー管理の権限を持つ最後の利用者は、権限を失わせない
- 認証の事象（ログインの成功・失敗・制限・ログアウト）は、構造化ログに残す（パスワード・トークンは残さない）。API の応答には、CSP・フレームの禁止・参照元なし・HSTS のヘッダーを付ける。**画面（静的ファイル）の応答にも、CloudFront が、CSP（同じオリジンだけを許可。インラインのスクリプト・eval・外部の資源は許さない。`frame-ancestors 'none'`）・`X-Frame-Options: DENY`・HSTS などを付ける**（Issue #127。`infra/lib/content-security-policy.ts`。手元の確認は `pnpm test:csp`）。画面の Zod は、`jitless` にして、CSP のもとで eval を試さない（`src/frontend/lib/zod-config.ts`）
- Web Push の購読の宛先は、https のドメイン名のみ（localhost・IP アドレスは不可）
- **Web Push の VAPID の秘密鍵**（#241）は、パラメータストア（SecureString。`/sfm/<環境>/web-push/vapid-private-key`）にだけ置く。環境変数・コード・ログ・エラーのメッセージ・コミットに含めない。配信のたびに、`SecretPort` から読む（保管先が、短時間キャッシュする）。公開鍵（`WEB_PUSH_PUBLIC_KEY`）と連絡先（`WEB_PUSH_SUBJECT`。アプリの https の URL。個人のメールアドレスは使わない）は、公開の値で、環境変数に置く。生成・登録・更新の手順は、operations.md 8.6。開発サイトと本番サイトで、同じ鍵を使い回さない
- **購読の暗号鍵（p256dh・auth）**（#241）は、購読ごとの値で、機密として扱う。購読の記録にだけ保存し、API の応答・ログ・エラーのメッセージに出さない。入力は、base64url の形式と長さを検証する
- データファイル（ローカル）は、所有者のみが読み書きできる権限（0600）で作る。バックアップ・復元は [backup-restore.md](../40_operations/backup-restore.md)

## AWS へのデプロイの認証・設定

顧客評価環境のデプロイ（`infra/`。[ADR-0006](../10_design/adr/0006-iac-cdk-and-same-origin-delivery.md)）には、次の決まりを適用する。

- **長期のアクセスキーを、GitHub にも、リポジトリにも、CI の設定にも置かない**。GitHub Actions は、OIDC の一時的な認証で、AWS のロール（`sfm-github-actions-deploy`）を引き受ける（セッションは 1 時間）
- ロールを引き受けられるのは、**環境ごとのロール**: 開発サイトのロール（`sfm-github-actions-deploy`）は、GitHub の Environment `development` のジョブだけ、本番サイトのロール（`sfm-github-actions-deploy-production`）は、Environment `production` のジョブだけ（信頼ポリシーの条件。互いに、引き受けられない）。Environment で、デプロイできるブランチ・承認者を、さらに制限する（本番サイトは、`main` だけ・承認者の承認が必須。開発サイトは、`develop`・`feature/*`・`release/*`・`hotfix/*`（`main` は含めない）。ADR-0013）。同じアカウントのため、ロールは、`cdk-*` のロールを引き受けられる点で、完全な分離ではない
- 信頼ポリシーの `sub` は、GitHub の**不変の ID の形式**（組織・リポジトリの ID を含む。`repo:<組織>@<ID>/<リポジトリ>@<ID>:environment:<Environment の名前>`）で書く。リポジトリの名前変更・移管・同名の別リポジトリによる、なりすましを防ぐため。旧形式（名前だけ）には戻さない（Issue #87）
- ロールの権限は、**CDK のデプロイ用ロール（`cdk-<識別子>-*`）を引き受けることだけ**。リソースの作成・変更は、CDK のデプロイ用ロールの権限で行う
- ロールの ARN にはアカウント ID が含まれるため、GitHub の **Environment のシークレット**（`AWS_DEPLOY_ROLE_ARN`）に設定する。リポジトリ（公開）には、アカウント ID・ドメイン名・ホストゾーン名を書かない（環境変数・GitHub の変数で渡す）。`cdk.context.json`（検索結果のキャッシュ）は、Git 管理外にする
- AWS に接続するコマンド（`cdk bootstrap`・`deploy`・`destroy` など）は、**ユーザーが、対象のアカウントのプロファイルを指定して実行する**。AI エージェントは、AWS への適用をしない（AGENTS.md 12 章）。実行ログ・出力のアカウント ID・ARN は、チャット・Issue・PR に貼らない
- API の Lambda の関数の URL は、認証なし（NONE）で公開される（CloudFront を経由しなくても呼べる）。**認証・認可は、アプリ側で必ず行い、認証なしで公開するのは、`/health` のような、安全な範囲に限る**
- cloudfront.net の既定の証明書は、最低の TLS のバージョンが固定される（TLS 1.0）。独自のサブドメイン（独自の証明書）にすると、TLS 1.2 以上にできる。顧客の評価は、独自のサブドメインで行う

## AIエージェントの権限管理

  - 対象例: `.env`, `.env.*`（`.env.example` を除く）、`**/*.pem`, `**/*.key`, `**/*credentials*`, 実データの格納ディレクトリ
- AIエージェントが守るルールは [AGENTS.md](../../AGENTS.md) の「10. セキュリティ・機密情報」に定める（二重管理を避けるため、ここには書かない）
