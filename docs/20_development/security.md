# セキュリティ・機密情報

目的: 秘密情報の管理、扱うデータの取り扱い、アプリケーションのセキュリティ、AIエージェントの権限管理を定める。

## 秘密情報の管理

秘密情報 = APIキー、パスワード、アクセストークン、DB接続文字列、証明書・秘密鍵、クラウドの認証情報、ロボット・センサー機器の接続認証情報など。

- 秘密情報はコードに直接書かず、環境変数から読み込む
- ローカル開発では `.env` に記載する。`.env` はGit管理対象外とし、必要な変数名とダミー値を `.env.example` に記載して共有する
- 本番・検証環境ではクラウドのシークレット管理サービス（例: Secret Manager / Key Vault 等。TODO: インフラ確定後に記載）を使い、`.env` ファイルを配置しない
- 環境（開発・検証・本番）ごとに異なる認証情報を使い、使い回さない
- 権限は必要最小限とする（最小権限の原則）。読み取り専用で足りる場合は書き込み権限を付けない
- 秘密情報をチャット・メール・Issue・PR・ドキュメントに貼り付けて共有しない
- 秘密情報を誤ってコミット・公開した場合は、履歴から消すだけでなく **直ちに該当の認証情報を無効化・再発行** し、関係者に報告する
- `.gitignore` に以下を含める
  - `.env`, `.env.*`（`.env.example` は除く）
  - `*.pem`, `*.key`, `*.p12` などの鍵・証明書ファイル
  - 認証情報ファイル（例: クラウドのサービスアカウントキー `*credentials*.json`）
  - ログ・ダンプ・実データのエクスポートファイル

## 扱うデータと取り扱い

| 区分 | 例 | 取り扱い |
|------|----|----------|
| 圃場・ハウスの運用データ | センサー値、ロボット稼働ログ、栽培・収量データ、ハウスの位置情報 | 協力農家・関係機関の機密情報として扱う。許可なく外部に公開・共有しない |
| 研究・評価データ | 第三者評価の結果、評価用データセット | 公開範囲は関係者の合意に従う |

- 実データ（本番・圃場由来のデータ）をリポジトリにコミットしない。テスト・サンプルには匿名化したデータか合成データを使う
- ログに個人情報・秘密情報・リクエスト本文全体を出力しない。必要な場合はマスキングする
- 外部サービス（生成AI・翻訳・オンラインツール等）に実データ・個人情報・秘密情報を入力しない

## アプリケーションのセキュリティ

- 通信は HTTPS / TLS で暗号化する。ロボット・センサーとサーバ間の通信も同様に暗号化・認証を行う
- 全てのAPIに認証・認可を設け、ユーザーの役割に応じて操作できる範囲を制限する。特にロボットやハウス設備の **遠隔操作・設定変更は、権限を持つ人だけが実行できる** ようにし、操作履歴を残す
- 外部入力（API・画面・センサーからのデータ）は必ず検証し、SQLインジェクション・XSS等を防ぐ（クエリはプレースホルダを使い、文字列結合で組み立てない）
- エラーメッセージに内部情報（スタックトレース、パス、SQL、設定値）を含めない
- 依存パッケージは信頼できるものを選び、脆弱性診断（例: `npm audit`、Dependabot）で定期的に確認する
- 開発用 API（全データの消去・時計の操作・ジョブの強制実行）は、環境変数 `DEV_API_ENABLED=true` と明示したときだけ有効にする（既定は無効）。本番（`APP_MODE=production`）と Lambda では、指定にかかわらず無効。E2E・負荷テストの設定でのみ、明示的に有効にする
- Lambda では、`APP_MODE`・`PERSISTENCE` を必ず明示する（既定の `local`・メモリで動かさない）
- ログインの試行回数の制限の接続元は、クライアントが付ける `X-Forwarded-For` を信頼しない。信頼するプロキシの段数（`TRUSTED_PROXY_HOPS`）を設定したときだけ、末尾から数えた値を使う
- ユーザーを削除したときは、そのユーザーのセッションと Web Push の購読も削除する。パスワードを再設定したときは、セッションを失効する。ユーザー管理の権限を持つ最後の利用者は、権限を失わせない
- 認証の事象（ログインの成功・失敗・制限・ログアウト）は、構造化ログに残す（パスワード・トークンは残さない）。API の応答には、CSP・フレームの禁止・参照元なし・HSTS のヘッダーを付ける
- Web Push の購読の宛先は、https のドメイン名のみ（localhost・IP アドレスは不可）
- データファイル（ローカル）は、所有者のみが読み書きできる権限（0600）で作る。バックアップ・復元は [backup-restore.md](../40_operations/backup-restore.md)
