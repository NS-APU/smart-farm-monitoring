## 1. 調べ方と、確認できなかったこと

- 調べたもの: 画面のコード（`src/frontend/pages/`・`components/`・`i18n/`・`styles/`）、機能仕様書（[functional-specification.md](../10_design/functions/functional-specification.md)。以下「機能仕様書」）、ユースケース、[as-built.md](../10_design/architecture/as-built.md)（実装と設計の差分。D-xx）、[dev_spec.md](../10_design/functions/dev_spec.md)（暫定仕様の一覧。4.1 の No.）、E2E のスクリーンショット（`test-result/e2e`）
- **スクリーンショットは、古い実行（2026-10 上旬）のもの**で、現在の画面と違う可能性がある。画像で確認した項目には、根拠に「画像」と書いた。縮小表示のため、文字の大きさ・表の切れ方を断定できないものは、「要確認」とした
- **確認できなかったこと**: AWS 上の実機での挙動（即時取得の応答時間・評価の更新が同期か非同期か・Cognito のパスワードの扱い・端末ごとの Web Push）、実際のタブレット・スマートフォンでの操作感、768px 幅の見た目
- **問題なしと判断した点**: ステータスを、色・アイコン・文字の 3 つで示している／設備・視点・期間・絞り込みが URL に反映され、再読み込みで保たれる／ログインの失敗メッセージが、ユーザー ID の存在を推測させない／戻り先（`next`）が外部へ誘導しない／検証エラー時に最初の項目へフォーカスする／削除確認のキーボード操作／認証情報を画面に出さない／パスワードの強度の検証（クライアント・サーバー）／自分自身を削除できない／SC-05・SC-11 の 900px 以下でのカード表示／空・読み込み中・エラーの共通の表示

  - **分類**: 要件ギャップ（要件・ユースケース・機能仕様書と実装のずれ）／機能の不足／操作性・レイアウト／顧客指摘（評価する人に見せたときに、指摘されそうな点）
