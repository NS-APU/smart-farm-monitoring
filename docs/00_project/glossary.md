# 用語集

目的: プロジェクト固有の用語・略語の表記と意味を統一する。新しい業務用語・略語を使う場合は、先にこの表へ追加する（[documentation-guidelines.md](./documentation-guidelines.md) 参照）。

## 記載ルール

- 一般的な教養があれば語句から意味を推測できる用語は載せない。載せるのは、略語、このプロジェクト固有の意味を持つ用語、一般的な意味と異なる用語のみとする
- 「定義」は、このプロジェクトでの意味を書く。一般的な意味と異なる場合は、その旨を明記する
- 別名・略称がある場合は「別名・略称」に記載し、文書中ではこの表の「用語」の表記に統一する
- 定義の出典となるドキュメントがあれば「参照」にリンクする

## 画面での呼び方

設計書・コード・ログで使う内部の用語のうち、農作業者に向けた画面では、別の言い方にするものを定める。画面の文言（aria-label・title・placeholder・エラーメッセージを含む）は、この表の「画面での呼び方」に統一する。内部の名前（識別子・ファイル名・コード中のコメント・ログ）と、要件・設計書の内部用語は、変えない（Issue #154）。
画面の名前を変えたものは、旧名と新名を載せる（旧名は、画面では使わない。Issue #155）。

| 内部の用語 | 画面での呼び方 | 画面の書き方 | 備考 |
|------------|----------------|--------------|------|
| 論理削除 | 画面では使わない | 「削除したデータは、一覧と集計の対象から外れます。変更履歴には残ります」の趣旨で書く | 手動入力・ステータスコード・設備の削除の方式（データを残し、削除済みの状態にする）。確認ダイアログの文言は、同じ趣旨に合わせる |
| メトリクス | 指標 | 「根拠の指標」「指標」（表の列見出し）のように、「指標」と書く | 観点の評価に使う算出値と、判断基準に使う値。判断基準の「指標」と同じ言葉に統一する |

| 取り込み設定・状況（SC-11 の旧名） | 取り込み | 見出し・リンクを、メニューと同じ「取り込み」と書く（リンクは「取り込みへ」） | メニューと見出しの名前をそろえる（Issue #155） |
