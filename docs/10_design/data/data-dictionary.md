# データ辞書

目的: 本システムで扱うデータ項目の名前・型・単位・取得元・意味を定義し、設計・実装・テストで同じ意味で使えるようにする。構造は [data-model.md](./data-model.md)、流れは [data-flow.md](./data-flow.md) を参照する。

> **記載のルール**
> - 項目は、日本語名（画面・文書で使う表記。[glossary.md](../../00_project/glossary.md) に従う）と、英語の識別子（コード・データでの名前。`camelCase`。[coding-standards.md](../../20_development/coding-standards.md)）を持つ
> - 「状態」が **仮** の項目は、ロボット・環境センサーのインターフェース仕様が未提供のため、構想時の項目を仮に採用したもの。**確定ではない**（rfp.md 7章、Q-001〜Q-004）。確定仕様の提供後に、差分を洗い出して更新する
> - 単位は、境界（入出力）で変換し、内部では1つの単位に統一する。単位が未確定のものは `TODO:` とする
> - 欠損は 0 で代用せず、値なし（欠損）として区別する。型の「null 可」は、欠損を表現できることを示す
> - 観点・メトリクスの算出式・判断基準は、重複を避けるため [viewpoint/](../viewpoint/) に書き、ここでは名前・単位のみを定義する

## 1. 共通の規則

| 項目 | 規則 |
|------|------|
| 時刻 | UTC の ISO 8601（例: `2026-10-09T03:00:00Z`）で保存・受け渡し。画面では日本時間（`Asia/Tokyo`）に変換して表示する |
| 識別子 | 設備ID・通知ID などは、システム内で一意な文字列。種類ごとに型で区別する（ブランド型） |
| 論理削除 | 設備・手動入力・ステータスコードは、削除しても、データを残し、削除済みの状態にする |
| 真偽値 | `is`・`has` で始める（例: `isDeleted`） |
| 列挙値 | 文字列リテラルの定数（`UPPER_SNAKE_CASE`）。画面の表示名は別に持つ |
| 欠損・未取得 | 欠損（取得したが値がない）は `null`、未取得（まだ来ていない）は項目なし。意味を混在させない |
