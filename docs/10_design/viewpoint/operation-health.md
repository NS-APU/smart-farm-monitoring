# 評価の運用面の観点

目的: ロボット・ハウスそのものではなく、評価を支えるデータの整備状況と、利用者の受け止め方を評価する観点（データ活用度合い・満足度）と、その判断基準を定める。共通のルールは [evaluation.md](./evaluation.md)、記載形式は [viewpoint-overview.md](./viewpoint-overview.md) を参照する。

> **基準の位置づけ**
> - 判断基準の数値は、構想時のプロトタイピング要件（`work/functional.requirements.md`）の既定値を仮に採用したもので、根拠は未確認。**暫定の値で運用し**、評価関係者に確認して見直す（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。[rfp.md](../requirements/rfp.md) の Q-007。確認事項は #209）
> - 「満足度」は、客観的な評価が難しい「倫理性」に置き換えた観点（RQ-014）。評価方法は、決定済み（[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209。Q-008）

## 1. データ活用度合い

| 項目 | 内容 |
|------|------|
| 観点名 | データ活用度合い |
| 対象 | モニタリングシステムが扱うデータ（ロボットデータ・環境センサーデータ・手動入力データ） |
| 目的 | 評価に必要なデータが、どれだけ取得・連携できているかに気づく |
| 指標・データ | **メトリクス**<br>・ロボットデータ取得数、環境センサーデータ取得数、手動入力データ取得数、全データ数<br>・データ連携率（%）= Σ取得データ数 ÷ Σ全データ数 × 100<br>**取得方法**: システムが内部で集計する<br>**ダッシュボード表示（主要）**: データ連携率。各取得数・全データ数は関連データとして参照できる |
| 判断基準 | ・データ連携率: 90%以上 → 正常 / 70%以上90%未満 → 注意 / 70%未満 → 異常<br>・最終ステータス: データ連携率で決める<br>・不明: 各取得数・全データ数が未取得、または全データ数 = 0 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が、取り込みの失敗や入力の漏れを確認して補う（UC-07）。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | 「全データ数」は、期間を、設備ごとの「古い」の基準（取得間隔 × 3、最低 3 分）のスロットに区切った総数（データの入口ごと。例: 7 日間で、ロボット（1 分）は 3 分のスロットで 3,360 個）。取得数は、値が 1 件以上あったスロットの数（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。実装は #216）。提供元の更新の頻度は、確認する（#193） |

## 2. 満足度

| 項目 | 内容 |
|------|------|
| 観点名 | 満足度 |
| 対象 | 他の9観点に対する、利用者（農作業者）の受け止め |
| 目的 | 数値には現れない、現場の使いやすさや納得感に気づく |
| 指標・データ | **メトリクス**<br>・満足度以外の9観点（収穫精度、収穫速度、環境適応性、操作性、メンテナンス性、コスト効率、安全性、データ活用度合い、耐久性）それぞれの 1〜5 スター評価（整数）<br>・総合満足度 = 9観点のスター評価の平均（小数第1位に丸める）<br>**取得方法**: 手動入力（農作業者の全員が、月に 1 回を目安に、1〜5 スターで入力する。9 観点すべてが揃わないと保存できない）<br>**ダッシュボード表示（主要）**: 総合満足度。詳細画面では、各観点の満足度をレーダーチャートで表示する |
| 判断基準 | ・総合満足度: 4.0以上 → 正常 / 3.0以上4.0未満 → 注意 / 3.0未満 → 異常<br>・評価に使う値: 各入力者の、期間内の最新の入力を取り、観点ごとに、入力者の平均を取る（1 人 1 票）。総合満足度は、その 9 観点の平均<br>・期間: 既定は直近 30 日（最終ステータスと、期間を選ばないときの表示）。期間を選べば、他の観点と同じ長期の期間。短期評価は持たない<br>・不明: 期間内に、9観点のいずれかの入力がない（入力が遅れると、前回の入力が期間から外れて「不明」になる。許容） |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。満足度の低い観点について、農作業者から所感を聞き取り、改善につなげる。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | 運用の前提（暫定）: 農作業者の全員が、月に 1 回を目安に入力する。入力者が複数のときは、1 人 1 票で集計する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。実装は #211）。誰が・どの頻度で入力するか、尺度（1〜5）と判断基準（4.0・3.0）の出典・意図は、秋田県立大学に確認する（#209。Q-008） |
