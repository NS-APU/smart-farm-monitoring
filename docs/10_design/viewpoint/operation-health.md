# 評価の運用面の観点

目的: ロボット・ハウスそのものではなく、評価を支えるデータの整備状況と、利用者の受け止め方を評価する観点（データ活用度合い・満足度）と、その判断基準を定める。共通のルールは [evaluation.md](./evaluation.md)、記載形式は [viewpoint-overview.md](./viewpoint-overview.md) を参照する。

> **基準の位置づけ**
> - 判断基準の数値は、構想時のプロトタイピング要件（`work/functional.requirements.md`）の既定値を仮に採用したもので、根拠は未確認。TODO: 根拠を確認し確定する（[rfp.md](../requirements/rfp.md) の Q-007）
> - 「満足度」は、客観的な評価が難しい「倫理性」に置き換えた観点（RQ-014）。評価方法は TODO: 定める（Q-008）

## 1. データ活用度合い

| 項目 | 内容 |
|------|------|
| 観点名 | データ活用度合い |
| 対象 | モニタリングシステムが扱うデータ（ロボットデータ・環境センサーデータ・手動入力データ） |
| 目的 | 評価に必要なデータが、どれだけ取得・連携できているかに気づく |
| 指標・データ | **メトリクス**<br>・ロボットデータ取得数、環境センサーデータ取得数、手動入力データ取得数、全データ数<br>・データ連携率（%）= Σ取得データ数 ÷ Σ全データ数 × 100<br>**取得方法**: システムが内部で集計する<br>**ダッシュボード表示（主要）**: データ連携率。各取得数・全データ数は関連データとして参照できる |
| 判断基準 | ・データ連携率: 90%以上 → 正常 / 70%以上90%未満 → 注意 / 70%未満 → 異常<br>・最終ステータス: データ連携率で決める<br>・不明: 各取得数・全データ数が未取得、または全データ数 = 0 |
| 基準の根拠 | 構想時の既定値。TODO: 根拠を確認する（Q-007） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が、取り込みの失敗や入力の漏れを確認して補う（UC-07）。内容は TODO |
| 確認事項 | TODO: 「全データ数」（期待されるデータの総数）の定義と算出方法。自動取り込みの仕様（Q-001）に依存する |

## 2. 満足度

| 項目 | 内容 |
|------|------|
| 観点名 | 満足度 |
| 対象 | 他の9観点に対する、利用者（農作業者）の受け止め |
| 目的 | 数値には現れない、現場の使いやすさや納得感に気づく |
| 指標・データ | **メトリクス**<br>・満足度以外の9観点（収穫精度、収穫速度、環境適応性、操作性、メンテナンス性、コスト効率、安全性、データ活用度合い、耐久性）それぞれの 1〜5 スター評価（整数）<br>・総合満足度 = 9観点のスター評価の平均（小数第1位に丸める）<br>**取得方法**: 手動入力<br>**ダッシュボード表示（主要）**: 総合満足度。詳細画面では、各観点の満足度をレーダーチャートで表示する |
