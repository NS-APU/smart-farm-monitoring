# ロボットの健全性の観点

目的: 収穫ロボットの健全性を評価する観点（収穫精度・収穫速度・操作性・メンテナンス性・コスト効率・安全性・耐久性）と、その判断基準を定める。共通のルール（ステータスの区分、不明の扱い、判定の組み合わせ方）は [evaluation.md](./evaluation.md) に従う。記載形式は [viewpoint-overview.md](./viewpoint-overview.md) を参照する。

> **基準の位置づけ（全観点共通）**
> - 判断基準の数値は、構想時のプロトタイピング要件（`work/functional.requirements.md`）の既定値を仮に採用したもの。出典・実測などの根拠は未確認で、確定値ではない
> - 既定値・算出式は暫定で、運用しながら、評価関係者に確認して見直す。算出式は、観点の詳細画面に、暫定であることとあわせて表示する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。実装は #220。[rfp.md](../requirements/rfp.md) の Q-007。確認事項は #209）
> - 判断基準は、運用で変更できる（[functional-requirements.md](../requirements/functional-requirements.md) の FR-5.7）。ここに書くのは既定値
> - データ項目の定義は、データ辞書（[data-dictionary.md](../data/data-dictionary.md)）と整合させる
> - 用語の「評価指標」は「観点」に統一する

## 1. 収穫精度

| 項目 | 内容 |
|------|------|
| 観点名 | 収穫精度 |
| 対象 | 収穫ロボット（収穫の品質） |
| 目的 | 傷つけずに、取り残さず、売れる果実を収穫できているかに気づく |
| 指標・データ | **メトリクス**<br>・可販果率（%）= 100 − ((誤収穫数 + 果実損傷数) ÷ 収穫数 × 100)<br>・取り残し率（%）= 取り残し数 ÷ (収穫数 + 取り残し数) × 100<br>・認識精度（%）= 100 − 取り残し率<br>・果実損傷率（%）= 果実損傷数 ÷ 収穫数 × 100<br>**データ項目**: 収穫数、果実損傷数、誤収穫数、取り残し数<br>**取得方法**: 手動入力（収穫数はロボットデータからの自動取得も想定）<br>**ダッシュボード表示（主要）**: 可販果率、認識精度。それ以外は詳細画面に表示する |
| 判断基準 | ・可販果率: 90%以上 → 正常 / 80%以上90%未満 → 注意 / 80%未満 → 異常<br>・認識精度: 90%以上 → 正常 / 80%以上90%未満 → 注意 / 80%未満 → 異常<br>・最終ステータス: 可販果率と認識精度のうち悪い方<br>・不明: 収穫数・果実損傷数・誤収穫数・取り残し数のいずれかが未取得、または収穫数 = 0 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する（UC-10）。農作業者が原因を確認して調整し（UC-05）、結果を記録する（UC-06）。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | 収穫数は、ロボットデータ（自動取り込み）から取り、手動入力でも入力できるようにする（#192）。手動入力の「収穫成功回数」「収穫試行回数」「誤認識数」は、参考の項目として残し、判定に使わない（決定。[ADR-0017](../adr/0017-evaluation-rules.md)）。収穫数の定義（試行を含むか）は、確認する（#193・#209） |

| 目的 | 収穫が遅い、または走行が止まりがちな状態に気づく |
| 指標・データ | **メトリクス**<br>・平均処理時間（秒/果実）= 収穫稼働時間 × 3600 ÷ 収穫数<br>・走行停止率（%）= 走行停止時間 ÷ 収穫稼働時間 × 100<br>・ステータス（ステータスコードのカテゴリ）<br>**データ項目**: 収穫稼働時間、走行停止時間、収穫数、ステータスコード<br>**取得方法**: ロボットデータ（自動取り込み）<br>**ダッシュボード表示（主要）**: 平均処理時間、ステータス、走行停止率。収穫稼働時間・走行停止時間は詳細画面 |
| 判断基準 | ・走行停止率: 5%未満 → 正常 / 5%以上10%未満 → 注意 / 10%以上 → 異常<br>・平均処理時間: 60秒未満 → 正常 / 60秒以上120秒未満 → 注意 / 120秒以上 → 異常<br>・ステータス: カテゴリ（正常／注意／異常）をそのまま判定とする<br>・最終ステータス: 上記のうち最も悪いもの<br>・不明: 収穫稼働時間・収穫数・走行停止時間・ステータスのいずれかが未取得、または収穫稼働時間 = 0、収穫数 = 0 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が走行・収穫の停滞の原因を確認して復旧・調整する（UC-05、UC-06）。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | TODO: 収穫稼働時間・走行停止時間・ステータスコードを、ロボットのデータとして取得できるか（Q-001、Q-003） |

## 3. 操作性

| 項目 | 内容 |
|------|------|
| 観点名 | 操作性 |
| 対象 | 収穫ロボット（人による操作のしやすさ） |
| 目的 | 操作が煩雑・ミスしやすい状態に気づく |
| 指標・データ | **メトリクス**<br>・操作エラー率（%）= 操作エラー数 ÷ 操作ステップ数 × 100（操作ステップ数 = 0 の場合は 0%）<br>**データ項目**: 操作時間（分）、操作ステップ数、操作エラー数<br>**取得方法**: 手動入力<br>**ダッシュボード表示（主要）**: 操作ステップ数、操作時間、操作エラー率。操作エラー数は詳細画面 |
| 判断基準 | ・操作ステップ数: 5回未満 → 正常 / 5回以上10回未満 → 注意 / 10回以上 → 異常<br>・操作時間: 10分未満 → 正常 / 10分以上30分未満 → 注意 / 30分以上 → 異常<br>・操作エラー率: 10%未満 → 正常 / 10%以上30%未満 → 注意 / 30%以上 → 異常<br>・最終ステータス: 上記3指標のうち最も悪いもの<br>・不明: 操作ステップ数・操作エラー数・操作時間のいずれかが未取得 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が操作の手順・設定を見直す。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | 「操作」は、ロボットの 1 回の作業（収穫の開始から終了まで）のために行った操作。1 件の入力 = その作業での値で、操作ステップ数・操作時間の評価は、期間内の入力の**平均**（1 作業あたり）（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。実装は #217）。判断基準が「1 回の作業あたり」を想定しているかは、確認する（#209） |

## 4. メンテナンス性

| 項目 | 内容 |
|------|------|
| 観点名 | メンテナンス性 |
| 対象 | 収穫ロボット（故障からの復旧のしやすさ） |
| 目的 | 復旧に時間がかかる、または異常状態が続く状態に気づく |
| 指標・データ | **メトリクス**<br>・MTTR（平均修復時間）= 復旧に要した時間 ÷ 故障回数（故障回数 = 0 の場合は 0）<br>・ステータス（ステータスコードのカテゴリ。表示はカテゴリ名ではなくステータス名称）<br>**データ項目**: 故障回数、復旧に要した時間（分）、ステータスコード<br>**取得方法**: 手動入力（復旧対応の記録）、ロボットデータ（ステータス）<br>**ダッシュボード表示（主要）**: ステータス、MTTR。故障回数・復旧に要した時間は詳細画面 |
| 判断基準 | ・ステータス: カテゴリ（正常／注意／異常）をそのまま判定とする<br>・MTTR: 4時間未満 → 正常 / 4時間以上8時間未満 → 注意 / 8時間以上 → 異常<br>・最終ステータス: 上記2指標のうち最も悪いもの<br>・不明: 復旧に要した時間・故障回数・ステータスのいずれかが未取得 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が復旧し、故障回数と復旧時間を記録する（UC-06）。この記録がMTTRの元データになる |
| 確認事項 | 復旧に要した時間は、分で入力し、MTTR は、時間（÷60）で判定する。「復旧に要した時間」は、故障回数と同じ入力の中の、復旧時間の合計（例: 故障 2 回・各 45 分なら 90）（決定。[ADR-0017](../adr/0017-evaluation-rules.md)） |

## 5. コスト効率

| 項目 | 内容 |
|------|------|
| 観点名 | コスト効率 |
| 対象 | 収穫ロボット（費用に対する成果） |
| 目的 | 費用に見合う収穫ができているか、稼働が安定しているかに気づく |
| 指標・データ | **メトリクス**<br>・可販果率（%）（収穫精度と同じ）<br>・平均処理時間（秒/果実）（収穫速度と同じ）<br>・MTBF = 稼働時間 ÷ 故障回数（故障回数 = 0 の場合は稼働時間）<br>・MTTR（メンテナンス性と同じ）<br>・稼働率（%）= MTBF ÷ (MTBF + MTTR) × 100<br>・経済生産性（EconomicProductivity）= (収穫成功率 × 収穫速度 × 可用率) ÷ 運用コスト<br>　収穫成功率 = 可販果率 ÷ 100、収穫速度 = 収穫数 ÷ 収穫稼働時間（個/時間）、可用率 = 稼働率 ÷ 100<br>・運用コスト = ロボットコスト + 人件費 + メンテナンス費 + 電気代<br>**データ項目**: ロボットコスト（円/h）、人件費（円/h）、メンテナンス費（円/h）、電気代（円/h）（決定。実装は #215）、収穫数、収穫稼働時間、稼働時間、故障回数、復旧に要した時間、果実損傷数、誤収穫数<br>**取得方法**: ロボットデータ＋手動入力<br>**ダッシュボード表示（主要）**: 可販果率、平均処理時間、稼働率、経済生産性。運用コストは詳細画面 |
| 判断基準 | ・可販果率: 90%以上 → 正常 / 80%以上90%未満 → 注意 / 80%未満 → 異常<br>・平均処理時間: 60秒未満 → 正常 / 60秒以上120秒未満 → 注意 / 120秒以上 → 異常<br>・稼働率: 95%以上 → 正常 / 90%以上95%未満 → 注意 / 90%未満 → 異常<br>・経済生産性: 参考の表示で、判定に使わない（1.2以上・1.0以上の既定値は、根拠が確認できるまで、判定から外す。決定。実装は #215）<br>・最終ステータス: 可販果率・平均処理時間・稼働率のうち最も悪いもの<br>・不明: 算出に必要な入力が未取得、または収穫数・収穫稼働時間・稼働時間・運用コスト合計のいずれかが 0 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が稼働状況・費用を見直す。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | 4 つの費用（ロボットコスト・人件費・メンテナンス費・電気代）は、すべて円/時間にそろえ、運用コスト（円/時間）= 4 項目の合計とする。**経済生産性は、根拠が確認できるまで、判定から外し、参考として表示する**（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。実装は #215）。稼働時間の取得元は、ロボットデータ（自動取り込み）と手動入力（#192）。経済生産性の定義・単位・判断基準の出典と、コストの入力元・集計期間は、確認する（#209） |

## 6. 安全性

| 項目 | 内容 |
|------|------|
| 観点名 | 安全性 |
| 対象 | 収穫ロボット（作業の安全） |
| 目的 | 緊急停止やヒヤリハットが増えている状態に気づく |
| 指標・データ | **メトリクス**<br>・緊急停止頻度（回/時間）= 緊急停止回数 ÷ 稼働時間<br>・ヒヤリハット頻度（回/時間）= ヒヤリハット回数 ÷ 稼働時間<br>**データ項目**: 緊急停止回数、ヒヤリハット件数、稼働時間<br>**取得方法**: 手動入力（回数）、ロボットデータ（稼働時間） |
| 判断基準 | ・異常: 緊急停止頻度 0.05回/時間以上、またはヒヤリハット頻度 0.20回/時間以上<br>・注意: 緊急停止頻度 0.01回/時間以上0.05回/時間未満、またはヒヤリハット頻度 0.05回/時間以上0.20回/時間未満<br>・正常: 緊急停止頻度 0.01回/時間未満、かつヒヤリハット頻度 0.05回/時間未満<br>・最終ステータス: 2指標のうち最も悪いもの<br>・不明: 緊急停止回数・ヒヤリハット回数・稼働時間のいずれかが未取得、または稼働時間 = 0 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が現場で安全を確認する。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | ヒヤリハット = 事故や損傷にはならなかったが、ロボットの動作で、人・作物・設備に、危害や損傷を与えかけた出来事。緊急停止を伴う出来事は、緊急停止に数え、ヒヤリハットには数えない。1 つの出来事を 1 件とし、気づいた時点で記録する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)）。現場の感覚との差は、確認する（#209） |

## 7. 耐久性

| 項目 | 内容 |
|------|------|
| 観点名 | 耐久性 |
| 対象 | 収穫ロボット（長く安定して動くか） |
| 目的 | 故障が増え、稼働が不安定になっている状態に気づく |
| 指標・データ | **メトリクス**<br>・MTBF = 稼働時間 ÷ 故障回数（故障回数 = 0 の場合は稼働時間）<br>・稼働率（%）= MTBF ÷ (MTBF + MTTR) × 100<br>・MTTR = Σ復旧に要した時間 ÷ Σ故障回数（故障回数 = 0 の場合は 0）<br>・ステータス（ステータスコードのカテゴリ）<br>**データ項目**: 稼働時間、故障回数、復旧に要した時間、ステータスコード<br>**取得方法**: ロボットデータ＋手動入力<br>**ダッシュボード表示（主要）**: ステータス、MTBF、稼働率。稼働時間・故障回数・MTTR は詳細画面 |
| 判断基準 | ・異常: ステータスが異常、またはMTBF 100時間未満、または稼働率 90%未満<br>・注意: ステータスが注意、またはMTBF 100時間以上500時間未満、または稼働率 90%以上95%未満<br>・正常: ステータスが正常、かつMTBF 500時間以上、かつ稼働率 95%以上<br>・最終ステータス: 上記3指標のうち最も悪いもの<br>・不明: 稼働時間・復旧に要した時間・故障回数・ステータスのいずれかが未取得 |
| 基準の根拠 | 構想時の既定値（暫定）。出典は未確認で、評価関係者に確認する（Q-007。確認事項は #209） |
| 見つかった異常への対応 | 注意・異常は通知する。農作業者が故障の傾向を確認し、保守を判断する。診断メッセージ・推奨アクションの文言は、ひな形と観点ごとの固定の 1 文。現場の対応手順は、確認する（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。確認事項は #209） |
| 確認事項 | MTTR の単位の換算は、メンテナンス性と同じ（決定。[ADR-0017](../adr/0017-evaluation-rules.md)） |
