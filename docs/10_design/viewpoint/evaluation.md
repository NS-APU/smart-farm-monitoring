# 観点別の評価方針

目的: 観点（[viewpoint-overview.md](./viewpoint-overview.md)）の評価に共通する、ステータスの区分、判定の組み合わせ方、データが足りない場合の扱い、短期・長期の視点、診断メッセージの付け方を定める。観点ごとのメトリクスと判断基準は、各観点の文書を参照する。

> 本書の数値・ルールは、構想時のプロトタイピング要件（`work/functional.requirements.md`）を元にした**暫定の方針**で、運用しながら、評価関係者に確認して見直す（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。[rfp.md](../requirements/rfp.md) の Q-007。確認事項は #209）。

## 2. ステータス

- 観点の評価結果は、次の4つのステータスのいずれかとする

| ステータス | 意味 |
|------------|------|
| 正常 | 判断基準を満たしている |
| 注意 | 正常ではないが、異常ほどではない。農作業者の確認が望ましい |
| 異常 | 判断基準を満たしていない。農作業者の対応が必要 |
| 不明 | 評価に必要なデータが足りず、評価できない |

## 3. 判定のルール

- 複数の指標で判定する観点は、各指標の判定のうち**最も悪い判定**を、観点の最終ステータスとする。悪い順は 異常 → 注意 → 正常
- 境界値は、判断基準の「以上」「未満」の記載に従う（例: 5%未満 → 正常、5%以上 → 注意）
- 判断基準の数値は既定値とし、運用で変更できる（FR-5.7）
- ステータスコードを使う判定では、ステータスコードに紐づくカテゴリ（正常／注意／異常）を判定の入力とする（FR-3）

## 4. データが足りない場合

- 判定に必要なデータが取得できない場合は、「不明」とする
- 除算の分母が 0 になる場合（例: 収穫数 = 0）も、「不明」とする。各観点で例外を定めているものは、その定義に従う（例: 操作ステップ数 = 0 の場合の操作エラー率は 0%）
- 「不明」の場合は、「データ不足のため評価できない」旨と、データの取得・入力を確認する推奨アクションを表示する
- 一部の指標だけ取得できている場合の扱いは、観点ごとに定める（例: 環境適応性は、取得できた指標だけで判定する）
- データの欠損・異常値・遅延の扱いは、次のとおり（決定。[ADR-0016](../adr/0016-ingestion-federation-rules.md)。FR-1.6）。**欠損**（値がない）と**不正**（型・範囲外、未定義のステータスコード、計測日時が受信より 5 分を超えて未来）は、評価に**使わない**（欠損は 0 で代用しない）。**遅延**（受信が計測から 60 分を超えて遅れた。60 分は設定値）は、評価に**使う**。評価に使える値が足りないときは「不明」。受信が評価時刻より後の値は、使わない（過去の評価を、当時知っていた値で再現する）。範囲外の数値（温度 −50〜100℃ など。データ辞書）は不正とする。外れ値（急な変化・同じ値の固着）の検出は、しない

## 5. 短期視点と長期視点

- 各観点を、短期視点と長期視点の2つで評価する（RQ-011）

| 視点 | 評価の元になるデータ |
|------|----------------------|
| 短期視点 | 直近値（最新の観測、直近の作業、当日の暫定値など、観点に応じた直近の集計） |
| 長期視点 | 選択した期間の集計値（環境適応性は期間の平均） |

- 長期視点の期間は、当日（1日）／直近7日／直近30日／直近60日／直近90日から選べる。既定は直近7日（満足度の既定は直近30日。実装は #223）
- 観点の最終ステータスは、短期視点・長期視点のうち「不明」を除いた**悪い方**とする。両方「不明」なら「不明」
- 視点ごとに、判定の対象となった期間（観測時刻または集計範囲）を表示する
- **短期は、直近 24 時間**（ローリング）。短期評価を持たない観点は、**コスト効率・耐久性・データ活用度合い・満足度**（長い期間・一定期間の指標のため。短期視点を選んでも、長期の推移を表示する）（RQ-011。決定。[ADR-0017](../adr/0017-evaluation-rules.md)。評価関係者に確認する。確認事項は #209。Q-009）
- 長期視点で表示する「期間の値」は、判定に使った値と同じ算出式を、期間全体に当てた値（日ごとの値の平均ではない）。推移の粒度は、当日が 1 時間ごと、7〜90 日が日ごと。ステータスの推移は、最終ステータスの履歴で、期間を変えても同じ（決定。[ADR-0017](../adr/0017-evaluation-rules.md)。実装は #214）

## 6. 診断メッセージと推奨アクション

- 各評価結果に、診断メッセージと推奨アクションを付ける。正常のときにも表示する（RQ-010）
- 診断メッセージには、判定の根拠となったメトリクスを示す（RQ-009）
- 判断基準を運用で変更した場合は、診断メッセージに「カスタムの判断基準による判定」であることを示す
- 診断メッセージは「{観点名}: {ステータス}。{指標ごとの値と判定}」。**「注意」「異常」のときは、最も悪い指標（同じ悪さなら、すべて）を、先頭に「原因: …」として示す**（例: 「収穫精度: 異常。原因: 可販果率 75.0%（異常）。認識精度 92.0%（正常）」。実装は #213）
- 推奨アクションは、ひな形と、観点ごとの固定の 1 文（注意と異常で同じ）。「不明」は、全観点共通の 1 文で、理由は診断メッセージに示す。現場の対応手順が確認できたら、文言を拡充する（確認事項は #209。Q-010。決定。[ADR-0017](../adr/0017-evaluation-rules.md)）

## 7. 通知の条件

- 観点のステータスが「注意」または「異常」になったとき、通知する（RQ-012、RQ-013、FR-7）
- 通知には、ステータス・観点名・診断メッセージを含める
- 同じ内容の通知を重複して出さない。**正常が一定時間（設定値。既定 15 分）続いたあとの悪化**を、新しい出来事として通知し、短い行き来は通知しない。**改善（異常 → 注意）は通知しない**。「注意 ⇄ 異常」だけの行き来は、同じ出来事（決定。[ADR-0019](../adr/0019-notification-rules.md)。実装は #236）
- **「不明」は通知しない**。「不明」は、状態の変化とみなさない（「異常 → 不明 → 異常」は、再通知しない）。欠損・遅延は、個別に通知しない（決定。[ADR-0019](../adr/0019-notification-rules.md)）
- 「正常」に戻ったときは、通知しない。通知ごとに、経過と回復日時を示し、利用者がメモを入力できる（決定。[ADR-0019](../adr/0019-notification-rules.md)。実装は #238・#239）
- 通知を受けた農作業者の対応は、HITLの流れ（[use-cases.md](../requirements/use-cases.md) の UC-05、UC-06）に従う

## 8. 判断基準の変更

- 判断基準は、システム全体で共通とする（利用者ごとの設定ではない）
- 数値の関係が成り立たない変更は保存できない（FR-5.7）
- 変更した基準は、詳細・ダッシュボード・通知の判定に使う。変更済みであることを識別でき、既定値へ戻せる
- 過去の評価は、再計算せず、保持する（判定に使った基準の版を残す）。推移グラフの背景の帯は、現在の基準で描き、画面に説明する。基準の変更による状態変化は、通知する（本文に「判断基準の変更による」。実装は #218）。保存前に、影響を確認できるプレビューを実装する（#165）（決定。[ADR-0017](../adr/0017-evaluation-rules.md)）
- 判断基準を変えた理由が設計上重要な場合は、[adr](../adr/) に記録する
