## 2. ステータス

- 観点の評価結果は、次の4つのステータスのいずれかとする

| ステータス | 意味 |
|------------|------|
| 正常 | 判断基準を満たしている |
| 注意 | 正常ではないが、異常ほどではない。農作業者の確認が望ましい |
| 異常 | 判断基準を満たしていない。農作業者の対応が必要 |
| 不明 | 評価に必要なデータが足りず、評価できない |

## 3. 判定のルール

- 複数の指標で判定する観点は、各指標の判定のうち**最も悪い判定**を、観点の最終ステータスとする。悪い順は 異常 → 注意 → 正常
- 境界値は、判断基準の「以上」「未満」の記載に従う（例: 5%未満 → 正常、5%以上 → 注意）
- 判断基準の数値は既定値とし、運用で変更できる（FR-5.7）
- ステータスコードを使う判定では、ステータスコードに紐づくカテゴリ（正常／注意／異常）を判定の入力とする（FR-3）

## 4. データが足りない場合

- 判定に必要なデータが取得できない場合は、「不明」とする
- 除算の分母が 0 になる場合（例: 収穫数 = 0）も、「不明」とする。各観点で例外を定めているものは、その定義に従う（例: 操作ステップ数 = 0 の場合の操作エラー率は 0%）
- 「不明」の場合は、「データ不足のため評価できない」旨と、データの取得・入力を確認する推奨アクションを表示する
- 一部の指標だけ取得できている場合の扱いは、観点ごとに定める（例: 環境適応性は、取得できた指標だけで判定する）
- データの欠損・異常値・遅延の扱いは、次のとおり（決定。[ADR-0016](../adr/0016-ingestion-federation-rules.md)。FR-1.6）。**欠損**（値がない）と**不正**（型・範囲外、未定義のステータスコード、計測日時が受信より 5 分を超えて未来）は、評価に**使わない**（欠損は 0 で代用しない）。**遅延**（受信が計測から 60 分を超えて遅れた。60 分は設定値）は、評価に**使う**。評価に使える値が足りないときは「不明」。受信が評価時刻より後の値は、使わない（過去の評価を、当時知っていた値で再現する）。範囲外の数値（温度 −50〜100℃ など。データ辞書）は不正とする。外れ値（急な変化・同じ値の固着）の検出は、しない

## 5. 短期視点と長期視点

- 各観点を、短期視点と長期視点の2つで評価する（RQ-011）

| 視点 | 評価の元になるデータ |
|------|----------------------|
| 短期視点 | 直近値（最新の観測、直近の作業、当日の暫定値など、観点に応じた直近の集計） |
| 長期視点 | 選択した期間の集計値（環境適応性は期間の平均） |

- 長期視点の期間は、当日（1日）／直近7日／直近30日／直近60日／直近90日から選べる。既定は直近7日
- 観点の最終ステータスは、短期視点・長期視点のうち「不明」を除いた**悪い方**とする。両方「不明」なら「不明」
- 視点ごとに、判定の対象となった期間（観測時刻または集計範囲）を表示する

## 7. 通知の条件

- 観点のステータスが「注意」または「異常」になったとき、通知する（RQ-012、RQ-013、FR-7）
- 通知には、ステータス・観点名・診断メッセージを含める
- 同じ内容の通知を重複して出さない
- 「不明」の扱い（通知するか）は TODO: 定める
- 通知を受けた農作業者の対応は、HITLの流れ（[use-cases.md](../requirements/use-cases.md) の UC-05、UC-06）に従う

## 8. 判断基準の変更

- 判断基準は、システム全体で共通とする（利用者ごとの設定ではない）
- 数値の関係が成り立たない変更は保存できない（FR-5.7）
- 変更した基準は、詳細・ダッシュボード・通知の判定に使う。変更済みであることを識別でき、既定値へ戻せる
- 判断基準を変えた理由が設計上重要な場合は、[adr](../adr/) に記録する
