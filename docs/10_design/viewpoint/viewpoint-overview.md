# 健全性評価の観点（概要）

目的: ロボットおよびハウスの健全性を評価する観点と、その判断基準の設計を蓄積する際の方針と記載形式を示す。個別の観点・基準は、このディレクトリに順次追加する。

## 位置づけ

- 本システムは、ロボットやハウスの状態をデータで見える化し、農作業者の早期対応（HITL）を支える（[goals.md](../../00_project/goals.md) 参照）
- 「何をもって健全／不調とみなすか」の観点と判断基準を設計としてここに残し、ダッシュボードの表示・アラート・HITLフローの設計の拠り所にする
- テスト・品質保証の観点（`30_quality/`）とは分け、ここではシステムが評価する対象（ロボット・ハウス）の健全性を扱う
- 観点の元になる要求は [rfp.md](../requirements/rfp.md)（RQ-014 ほか）、観点を使う機能は [functional-requirements.md](../requirements/functional-requirements.md) を参照する

## 対象

| 対象 | 内容 |
|------|------|
| ロボット | イチゴ収穫ロボットの稼働状態・動作の健全性 |
| ハウス | スマートハウス（環境・設備）の健全性 |
| 評価の運用面 | 評価を支えるデータの整備状況と、利用者の受け止め（ロボット・ハウスそのものではない） |

## 蓄積の進め方

- 対象（ロボット／ハウス／評価の運用面）ごと、または観点のまとまりごとにファイルを分けて追加する
- 追加したファイルは [document-index.md](../../00_project/document-index.md) に追記する
- 判断基準の数値・閾値は、根拠（出典・実測・合意の経緯）とあわせて記載し、根拠のない値を確定値として書かない（未確定は `TODO:` と明記する。根拠が確認できないまま運用する既定値は、「暫定」と明記する。[ADR-0017](../adr/0017-evaluation-rules.md)）
- 観点や基準を採用・変更した理由が設計上重要な場合は、[adr](../adr/) に記録する
- 観点で使うデータ項目は、[data-dictionary.md](../data/data-dictionary.md) の定義と整合させる

## 観点の記載形式

観点ごとに、次の項目を記載する。

| 項目 | 内容 |
|------|------|
| 観点名 | 何の健全性を見るか（例: 稼働状態、環境、設備） |
| 対象 | ロボット／ハウス、対象の機器・部位 |
| 目的 | その観点で何に気づけるようにするか |
| 指標・データ | 判断に使うデータ項目（データ辞書の項目名）、取得方法（自動／手動） |
| 判断基準 | 正常／注意／異常などの区分と、その条件（閾値・期間・組み合わせ） |
| 基準の根拠 | 出典・実測値・合意の経緯 |
| 見つかった異常への対応 | 通知先・表示方法、HITLでの農作業者の対応 |
| 確認事項 | 未確定事項（`TODO:`） |

## 評価方針

観点に共通する評価方針（ステータスの区分、判定のルール、データが足りない場合、短期・長期の視点、通知の条件）は [evaluation.md](./evaluation.md) に記載する。
