# 機能要件

目的: 本システム（稼働モニタリング基盤）が備える機能を定め、設計・実装・テストの拠り所とする。要求は [rfp.md](./rfp.md)、利用の流れは [use-cases.md](./use-cases.md) を元にしている。

> **記載のルール**
> - 各要件の「根拠」に、元になった要求ID（rfp.md の RQ-xxx）と、関連するユースケース（UC-xx）を示す
> - 根拠が「提案」の要件は、発注者の要求にはなく、構想時のプロトタイピング要件（`work/functional.requirements.md`）や受注者の判断で加えたもの。発注者への確認が必要（確認していない間は暫定）
> - 評価観点のメトリクス・判断基準は、重複を避けるため [viewpoint/](../viewpoint/) に書き、ここでは書かない
> - データ項目の詳細は [data-dictionary.md](../data/data-dictionary.md) で定義する
> - 未確定の事項は `TODO:` と明記し、確認事項の番号（rfp.md の Q-xxx）を添える
> - 本システムはロボット・ハウスの自動制御を行わない（[goals.md](../../00_project/goals.md)）

| FR-3.2 | ステータスコードの定義を、登録・編集・削除・参照できること。同じコード値の重複登録はエラーとする。削除時は確認を求める | 提案 |

| FR-3.4 | 観点の評価（収穫速度・メンテナンス性・耐久性）は、ステータスコードのカテゴリを判定の入力に使うこと | 提案 / [robot-health.md](../viewpoint/robot-health.md) |

## FR-9. 認証・ユーザー管理

利用者は10名ほど。ログインは必須で、ロールは、管理者・一般の 2 種類とする（決定: [ADR-0013](../adr/0013-environments-and-access-control.md)。Issue #78）。以下は、構想時の要件と、[security.md](../../20_development/security.md)（全APIに認証・認可を設ける）にもとづく暫定の要件。

| ID | 要件 | 根拠 |
|----|------|------|
| FR-9.1 | ユーザーIDとパスワードで、ログイン・ログアウトできること。未認証のアクセスは、ログイン画面へ誘導すること | 提案 / security.md |
| FR-9.2 | ログインの試行回数を制限すること（構想時は、同一の接続元から15分あたり5回まで）。パスワードは、8文字以上で英大文字・英小文字・数字を含むものとし、ハッシュ化して保存すること | 提案 / security.md |
| FR-9.3 | セッションの有効期限を設けること（構想時は、アクセストークン30分、リフレッシュトークン7日）。TODO: 方式は設計で決める | 提案 |
| FR-9.4 | ユーザーを、一覧参照・登録・編集・削除できること。ユーザーID（一意）・ユーザー名・パスワード・ロールを持ち、最終ログイン日時を確認できること | 提案 |
| FR-9.5 | 操作を、ロールに応じて制御すること。**ロールは、管理者・一般の 2 種類**。管理者は、すべての操作ができる。一般は、**割り当てられた設備の閲覧（取り込みの状況・ログ、連携のログを含む）・手動入力（登録・修正・削除。他人の入力にも）・自身のユーザー情報の編集**に限る。操作ごとの可否は、[ADR-0013](../adr/0013-environments-and-access-control.md) の表。**実装は、Issue #115・#116（未実装。それまでは、全員が全権限を持つ 1 ロール）** | 決定（Issue #78）/ Q-017 |
| FR-9.6 | 設備の登録・管理は、**管理者のロールが行う**（一般は、閲覧のみ）。FR-9.5 に合わせる（構想時の「農作業者が行う（管理者を区別しない）」は、置き換える） | UC-12 / 決定（Issue #78） |
| FR-9.7 | ログインしている本人が、自分のユーザー情報（ユーザー名・パスワード）を編集できること（一般を含む。ロール・ユーザーID は、変えられない）。**実装は、Issue #115（未実装）** | 決定（Issue #78） |
| FR-9.8 | 管理者が、一般ユーザーごとに、閲覧できる設備を、**ハウス単位**で割り当てられること。割り当てがない一般ユーザーは、何も閲覧できず、割り当てのない設備は、存在しないものとして扱う。取り込みの状況・ログ、連携のログも、割り当てられた設備に関するものだけを見せる（現在は、ログが設備に結び付いておらず、持ち方の設計が要る。Issue #116）。管理者は、全設備を閲覧できる。**実装は、Issue #116（未実装）** | 決定（Issue #78） |
