# 非機能要件

目的: 本システム（稼働モニタリング基盤）の、機能以外の要件（コスト、構成、性能、可用性、セキュリティ、運用保守、使いやすさ、拡張性）を定め、設計・実装・テストの拠り所とする。要求は [rfp.md](./rfp.md) を元にしている。

> **記載のルール**
> - 各要件の「根拠」に、元になった要求ID（rfp.md の RQ-xxx）を示す。根拠が「提案」の要件は、発注者の要求にはなく、構想時のプロトタイピング要件（`work/non-functional.requirements.md`）や受注者の判断で加えたもの。発注者への確認が必要（確認していない間は暫定）
> - 数値は、根拠のある値と、暫定の値（構想時の目安）を区別する。暫定の値は「暫定」と書き、確定したら外す
> - 構成の選定（利用するAWSサービス、コンテナ構成など）は、ここに書かず、[architecture.md](../architecture/architecture.md) と [adr](../adr/) で決める。ここでは、構成が満たすべき条件を定める
> - 開発プロセス（テスト、コード品質、バージョン管理）は、[test-policy.md](../../30_quality/test-policy.md)、[coding-standards.md](../../20_development/coding-standards.md)、[git-workflow.md](../../40_operations/git-workflow.md) に従う
> - 未確定の事項は `TODO:` と明記する

| NFR-1.2 | AWSの利用は、払い出されたIAMユーザーの権限の範囲で行えること。その範囲で利用できないサービス・操作に依存しないこと。TODO: 秋田県立大学のAWSから宇都宮大学のファイルサーバーへ接続できるか（Q-002） | RQ-015 / rfp.md 7章 |

| NFR-1.4 | 初期構築のコストを抑えること。TODO: 目安額 | RQ-016 |
| NFR-1.5 | 不要なリソースの自動停止・削除と、コストの監視・アラートの仕組みを検討すること（検討の結果: 自動の監視・アラートは設けない。費用が想定を著しく超える場合は、発注者に相談する。architecture.md 11.1） | 提案 / RQ-017 |
| NFR-1.6 | コストを抑えるため、常時稼働を前提とした高価な構成（常時起動のマネージドサービスなど）は、必要性とコストを検討したうえでなければ採用しないこと（元の文は採用を促す読み方もできたため、意図を明確化） | RQ-017, RQ-021 |

構成: **サーバーレス構成を基本とする**（理由はコストの最小化と、同じ発注者での実績。[ADR-0002](../adr/0002-deployment-serverless.md)）。構想時の構成案（AWS EC2 上の Docker コンテナ）は採らない。前提条件（IAM権限、ファイルサーバーの接続元IP制限）が満たされない場合のみ、代替の構成を使う（architecture.md 11.2）。

## NFR-2. 構成・設計の原則

| ID | 要件 | 根拠 |
|----|------|------|
| NFR-2.1 | 農業情報基盤とのデータ連携を行いつつ、農業情報基盤に依存せず、単独で継続して稼働できること。農業情報基盤が停止していても、データの取り込み・評価・表示・通知が影響を受けないこと | RQ-007 |
| NFR-2.2 | 農業情報基盤との連携部分を、インターフェースとして切り離し、連携方式の変更・拡張に対応できること。TODO: 連携方式（API、データモデル、頻度）（Q-005） | RQ-006, RQ-020, RQ-021 |
| NFR-2.3 | ファイルサーバーからの取り込み部分を、インターフェースとして切り離し、接続先やファイルの仕様の変更の影響を、その部分に閉じ込められること | RQ-001, RQ-002, RQ-021 |
| NFR-2.4 | ロボット・センサー・ハウスの追加に、構成の変更で対応できること | RQ-005, RQ-019 |
| NFR-2.5 | 疎結合・低コスト・拡張性・継続運用性を重視した構成にすること | RQ-021 |
| NFR-2.6 | データ取得 → 蓄積 → 分析（評価）→ 可視化の各段階を分離し、各段階の入出力を定義して、単体でテストできること | 提案 |
| NFR-2.7 | 新しい観点の追加や、判定のロジックの差し替えが容易な構造にすること | 提案 / RQ-019 |
| NFR-2.8 | 2025年度のプロトタイプ・メトリクス定義などの成果物は再利用しない（FIWARE連携のインターフェースの資産の活用は、農業情報基盤との連携の設計で別途検討する） | rfp.md 7章 |
| NFR-2.9 | 仮決めの仕様にもとづく取り込み部分を、仕様の確定・変更の際に、取り込み部分の差し替えと、要件・設計・テストの更新で対応できる構造にすること（FR-1.11, FR-1.12） | rfp.md 7章 / RQ-019, RQ-021 |
