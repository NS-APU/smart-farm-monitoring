# ADR-0022 ファイルサーバーの接続（HTTP）の暫定設計（#172）

- ステータス: 承認（2026-11-05。ユーザーの判断。Issue #172）。暫定（接続先・アクセス方法が決まったら、見直す。D-01・#173）
- 日付: 2026-11-05
- 更新（2026-11-06。#119）: **ファイルパスは、取り込み元の接続設定ではなく、設備ごとに持つ**ことにした（[ADR-0023](./0023-http-file-source-per-equipment-file.md)）。接続設定の `filePath`（1 取り込み元 = 1 ファイル）は廃止し、保存済みの設定に残る `filePath` は、読み出すときに無視する。ファイルの一覧・取得・接続テストは、ADR-0023 のとおり実装した（以下の「ファイルパス」「接続テスト」「取得」の記述は、この更新で置き換わる）。
- 関連: [ADR-0003](./0003-ingestion-adapter-and-provisional-spec.md)、[ADR-0015](./0015-provisional-policy-external-specs.md)、[ADR-0016](./0016-ingestion-federation-rules.md)（SecretPort は D-55）、[architecture.md](../architecture/architecture.md) 5.1、[security.md](../../20_development/security.md)、[functional-specification.md](../functions/functional-specification.md) SC-11

目的: ファイルサーバーの接続の方式と接続先を、画面から設定して切り替えられるようにするための、暫定の設計（設定の項目・検証・接続テスト・内部のアドレスの扱い）と、実行環境（Lambda）からのアクセス手段の比較を、記録する。実際のファイルの取得（一覧・読み取り）のアダプタは、#119 で作る。

## 背景

- 宇都宮大学のファイルサーバーは、rsync でアクセスできると伺っている。ただし、これは「アクセスできる」という案内で、rsync を前提にしない（ADR-0015）。HTTP でアクセスできるかは、**不明**。
- 接続先・アクセス方法の回答は、得られていない（確認は #173・#255）。回答を待たずに進めるため、**HTTP（HTTPS）でアクセスできると仮定**して、設定と接続テストを作る。アクセスの手段が変わったら、方式（`type`）を増やして対応する。
- 接続先は、管理者が画面から設定できる。そのため、Lambda から、内部のアドレス（AWS のメタデータなど）へ、リクエストを送らせてしまう危険（SSRF）を、設計に含める。

## 決定

### 1. 設定の項目（取り込み元ごと。`connection`）

| 項目 | 内容 |
|------|------|
| 接続方式（`type`） | `MOCK`（ディレクトリ・S3 のモック。これまでの動作）／`HTTP`。**保存のない既存の設定は `MOCK`**（データの移行は、不要） |
| プロトコル（`protocol`） | `HTTPS`（既定）／`HTTP` |
| ホスト（`host`） | FQDN・IPv4・`[IPv6]`。スキーム・ポート・パス・認証情報を含められない。小文字にそろえる |
| ポート（`port`） | 1〜65535。省略は、プロトコルの既定（HTTPS は 443、HTTP は 80） |
| ファイルパス | ~~`filePath`（1 取り込み元 = 1 ファイル）~~ **廃止**（ADR-0023）。設備ごとの `sourceFilePath` に移した。形式（`/` で始まる、ファイル 1 つ。英数字と `. _ ~ ! $ & ' ( ) * + , ; = : @ / -` のみ。`..`・`?`・`#`・空白・`%` は使えない。500 文字以内）は、同じ |
| 認証方式（`authMethod`） | `NONE`（既定）／`BASIC`（ユーザー名・パスワード）／`BEARER`（トークン）／`API_KEY`（API キー） |
| API キーのヘッダー名（`apiKeyHeaderName`） | 既定は `X-API-Key`。`Host`・`Authorization`・`Content-Length` など、認証・メッセージの区切り・接続の制御に関わる名前は使えない |

- ~~1 取り込み元 = 1 ファイル~~ → 設備ごとに 1 ファイル（ADR-0023）。
- 既存の `connectionRef`（接続設定の参照名）は、互換のため残す。HTTP の接続では、使わない。見直しは、#119 で行う。
- **認証情報の値は、設定に持たない**。値は、SecretPort（#206）の `file-server/<取り込み元の識別子>` に置く（NFR-5.4）。値の形式: `BASIC` は JSON `{"username":"…","password":"…"}`（ユーザー名に `:` を含められない）、`BEARER` はトークン、`API_KEY` は API キー。値は、SC-11 の「認証情報」から、管理者が、書き込み専用で登録する（#207。D-47。保存済みの設定の認証方式で登録する。変更履歴には、「認証情報を更新した」という事実と認証方式だけを残す）。
- 設定と変更履歴には、ホスト・ポート・ファイルパスを含む（秘密情報ではなく、管理者だけが参照できる。値は、含まれない）。

### 2. 接続テスト

- `HEAD` で、**ファイルパスが設定された最初の設備のファイル**の有無を確かめる（ADR-0023）。`405`・`501` のときは、先頭 1 バイトだけの `GET`（`Range: bytes=0-0`）で確かめる（本文は、取得しない）。応答を待つ時間は 10 秒。
- 成功は 2xx（と、空のファイルの `416`）。失敗は、**理由だけ**を、固定の文言で示す（利用者に見せる。ログにも同じ）: 認証情報が設定されていません／認証情報の形式が正しくありません／認証情報を読み出せません／認証に失敗しました（401・403）／ファイルが見つかりません（404・410）／ファイルサーバーがエラーを返しました（5xx）／想定外の応答／リダイレクト／接続できません／応答しません／証明書を確認できません／暗号化通信に失敗しました／内部のアドレスには接続できません。**接続先・ファイルパス・認証情報・ネットワークのエラーの詳細は、出さない**。
- 認証に失敗したときは、秘密情報を、キャッシュを使わず取り直し（`refresh`）、値が変わっていれば、**1 度だけ**再試行する（認証情報の更新が、キャッシュの期間〔5 分〕のあいだ反映されないのを避ける。#206）。
- ~~画面の「即時取得」・自動の取り込みは、接続方式が HTTP のとき、「まだ使えません」の失敗として記録される~~ → **#119 で、一覧・取得を実装した**（ADR-0023。設備ごとのファイルパス）。

### 3. 内部のアドレスの拒否（SSRF の対策）

- **拒否する**: ループバック・プライベート（10/8・172.16/12・192.168/16）・リンクローカル（169.254/16。AWS のメタデータを含む）・キャリアグレード NAT・予約済み・マルチキャスト・ドキュメント用の IPv4、IPv6 の同等の範囲（`::1`・`fc00::/7`・`fe80::/10`・`fec0::/10`・`ff00::/8`・`2001:db8::/32`）、IPv4 を埋め込む形（IPv4 マッピング・互換・NAT64・6to4）は、埋め込まれた IPv4 で判定する。判定できない値は、拒否する（安全側）。
- **名前**: `localhost`・`*.localhost`・`*.internal`・`*.local`・`*.lan`・`*.home.arpa`・`*.intranet` と、数字だけ・16 進の名前（`127.1`・`2130706433`・`0x7f.0.0.1`。名前の解決で、IP アドレスとして解釈されるため）を拒否する。
- **保存のとき**と**接続の直前**に、検査する。名前は、**接続の直前の名前の解決の結果（すべての IP アドレス）**を検査し、1 つでも内部なら拒否する（DNS リバインディングの対策。保存のあとに、名前の指す先が変わっても、防げる）。
- **リダイレクトには従わない**（内部のアドレスへの誘導を避ける）。
- `HTTP_FILE_SOURCE_ALLOW_PRIVATE=true` のときだけ、内部のアドレスを許可する（ローカル・E2E・テスト用。**`APP_MODE=production` では、指定しても無効**。開発サイト・本番には、設定しない）。
- 平文の HTTP は、**許可し、画面に警告する**（暗号化されない旨と、HTTPS の推奨）。接続先が HTTPS に対応していない可能性があるため（architecture.md 5.1 の「暗号化のない方式は採らない」の例外ではなく、設定で選ぶ暫定の扱い。接続先が決まったら、見直す）。

### 4. 実行環境（Lambda）からのアクセス手段の比較（机上の整理。到達性は、接続先が決まるまで、未確認）

| 手段 | Lambda からの実現 | 追加の部品・費用 | 留意点 |
|------|------------------|------------------|--------|
| HTTPS（本設計） | Node.js 標準の `https` で足りる。**依存の追加なし** | なし | サーバーが HTTP でファイルを公開している必要がある（**不明**）。接続元 IP の制限があると、固定 IP が要る |
| SFTP | `ssh2` などのライブラリが要る（**依存の追加**）。ポート 22 の外向きの通信が要る | ライブラリ。固定 IP が要るなら、下の「固定 IP」 | 鍵・パスワードの管理は、SecretPort（#206）で足りる。接続の確立に時間がかかる（実行時間の上限 29 秒〔API〕に注意） |
| rsync | Lambda の標準の実行環境（Node.js）には、`rsync`・`ssh` の実行ファイルがない。レイヤー・コンテナイメージで同梱する必要がある。rsync は、ファイルの一覧・差分の転送に向くが、1 つのファイルを随時読む用途では、過剰 | 実行ファイルの同梱（サイズ・メンテナンス）。固定 IP が要るなら、下の「固定 IP」 | SSH の経路が要る。プロセスの起動を伴い、コールドスタートに影響しうる |
| 中継（S3 に置いてもらう） | 既存の S3 版（ADR-0012）の応用。Lambda → S3 の読み取りだけ | S3 の保管費用（小さい）。IAM（書き込み用の権限を、宇都宮大学側に渡す方法が要る） | 宇都宮大学側（または運用者）の作業が要る。実時間性は、置く頻度による |
| 固定 IP（接続元の制限がある場合） | Lambda を VPC に入れ、NAT ゲートウェイ + Elastic IP で、外向きの IP を固定する | **NAT ゲートウェイは、常時課金**（architecture.md 11 章では、数千円増。月 5,000 円の上限に対して、不利） | 必要になったときだけ、採る。ADR-0002 の前提 |

- 実際の到達性（宇都宮大学のファイルサーバーに、AWS から届くか・通信の許可・実行時間）は、**接続先が決まるまで、確かめられない**（#173）。アダプタ（#119）の着手の前に、接続先の確認結果で、手段を選ぶ。
- 本設計の `type` は、手段ごとに追加する（例: `SFTP`）。画面・API・検証・変更履歴の枠組みは、共通で使える。

## 検討した選択肢

| 選択肢 | 判断 |
|--------|------|
| 接続設定を、環境変数・IaC で持つ | 画面から切り替える要件（#172）に合わない。接続先の変更に、デプロイが要る |
| 接続設定に、認証情報の値を含める | NFR-5.4（認証情報の値は、設定・ログ・画面に出さない）に反する |
| 内部のアドレスを、拒否しない | 管理者の権限の奪取・設定の誤りで、メタデータサービス（169.254.169.254）などへ、リクエストを送れてしまう。拒否する |
| 保存のときだけ、検査する | 名前の指す先が、保存のあとに変わる（DNS リバインディング）と、防げない。接続の直前にも、検査する |
| リダイレクトに従う | 内部のアドレスへ誘導されうる。従わない（ファイルサーバーが、リダイレクトを返す場合は、設定のホスト・パスを直す） |
| 平文の HTTP を、拒否する | 接続先が HTTPS に対応しているか不明。拒否すると、確認前に、試せない。許可して、警告する |
| 複数のファイル（ディレクトリ・ワイルドカード）を指定できる | 1 ファイルを随時更新する方式（ADR-0015）。複雑さと、パスの検証の範囲が増える。1 取り込み元 = 1 ファイルにする |

## 結果

- 接続方式と接続先を、画面から設定して切り替えられる。接続テストで、設定と認証情報を確かめられる。取得は、ADR-0023（#119）。
- 内部のアドレスへのリクエストを、設計で防ぐ。ローカル・テストだけ、環境変数で許可する。
- 認証情報の値は、設定・変更履歴・ログ・画面・エラーに出ない。
- データスキーマの変更: 取り込み元の設定（`settings` のキー `ingestion.sources`）に、`connection` を加える（保存がなければ `MOCK`。移行は、不要）。IaC・依存パッケージの変更は、ない。
- 見直しの条件: 接続先・アクセス方法が決まったとき（#173）。HTTP でアクセスできないと分かったとき（`HTTP` を外すか、別の方式を足す）。
