# ADR-0002 デプロイ構成は、サーバーレスを基本とする

- ステータス: 承認（サーバーレスを基本とする方針。IAM権限・接続元IP制限の確認は、前提条件として残る）
- 日付: 2026-10-09
- 関連: [architecture.md](../architecture/architecture.md) 11章、RQ-015〜RQ-018 / NFR-1, NFR-4, NFR-6、[ADR-0001](./0001-modular-monolith-ports-and-adapters.md)

## 背景

- 秋田県立大学のAWS環境に、払い出されたIAMユーザーの権限でデプロイする（NFR-1.1, NFR-1.2）
- AWSの利用費は月5,000円以内（NFR-1.3）。ただし上限であり、目標は「可能な限り低コスト」（NFR-1.6、RQ-017）。運用・保守の負荷も抑える（RQ-018）
- 規模は小さい（利用者10名、ハウス1：ロボット1：センサー1、1日あたり数百〜数千レコード）。常時稼働の高価な構成は、規模に見合わない
- 構想時の構成案は、EC2 上の Docker コンテナだった。EC2 だけでなく、Amplify、Lambda、ECS/Fargate、Lightsail、App Runner などのAWSのマネージドサービスを、コスト最適化のベストプラクティス（使った分だけ支払う、マネージドで運用を減らす、支出を計測・監視する）で比較した

## 決定

**サーバーレス構成を基本とする。**

- 画面: Amplify Hosting（または S3 + CloudFront）
- API・取り込み・評価・連携・通知: Lambda（関数のURL、EventBridge のスケジューラ）
- DB: DynamoDB
- 認証: Amazon Cognito
- IaC・CI/CD: Amplify Gen 2（または CDK）

理由は、次の2つ。

1. **コストが最小である**（下の比較）。固定費がほぼなく、利用量に応じた課金で、規模に見合う
2. **同じ発注者（秋田県立大学）から委託を受けたこれまでのプロジェクトで、サーバーレス構成の実績がある**（受注者の知見）。構成・運用のノウハウを再利用でき、同じ環境での権限・運用の見通しが立てやすい。TODO: 該当するプロジェクトの概要（構成、使用したサービス、運用実績、IAM権限の範囲）を追記する

運用上の決め事:

- ドメイン・評価のロジックは、Amplify のデータ層（AppSync等）に依存させず、ポートとアダプタの外側に置く（ADR-0001）。ロックインを避ける
- Amplify が IAM で許されない場合は、S3 + CloudFront と CDK（または手順書）で、同じ構成を作る
- 共通のコスト削減の原則（常時課金の部品を持たない、ストレージ・ログ・バックアップを小さく保つ、など）は、architecture.md 11.1 に従う
- 前提条件（IAM権限、ファイルサーバーの接続元IP制限）が満たされない場合のみ、次の代替を使う。その場合は、新しい ADR で変更を記録する
  - 代替1: Lightsail 1台（SQLite）
  - 代替2: EC2 最小 1台（SQLite）
  - 規模・要求が増えて、コンテナ運用が必要になった場合の移行先: ECS on Fargate

## コストの比較

東京リージョン、1ドル150円の概算。**単価は第三者の料金一覧・AWSの告知・解説記事にもとづくもので、公式の料金表では未確認**。実際の請求で検証する（architecture.md 11.5）。

| 案 | 構成 | 月額の見込み | 年額の見込み | 固定費 |
|----|------|--------------|--------------|--------|
| **サーバーレス（採用）** | Amplify Hosting + Lambda + DynamoDB + Cognito | **数百円**（無料枠に収まれば、ほぼ0円〜） | 数千円 | ほぼなし |
| Lightsail 1台 | $5〜7のプラン（IPv4・1TB転送・ストレージ込み）。SQLite | 約750〜1,050円 | 約9,000〜12,600円 | あり |
| EC2 最小 1台 | t4g.micro（約1,200円）+ 公開IPv4（約550円）+ EBS（約300円）。SQLite | 約2,000円 | 約24,000円 | あり |
| ECS on Fargate | 最小のタスク（0.25 vCPU、0.5GB）常時1つ（約1,700円）+ 公開IPv4（約550円）+ ログ等。ALBを置くと数千円増 | 約2,300〜2,500円 | 約28,000〜30,000円 | あり |
| ECS/EKS + RDS・Aurora | Aurora Serverless v2 は 0.5 ACU の常時稼働で約6,500円以上 | 5,000円超 | 6万円超 | 大きい |
| AWS App Runner | - | - | - | 採用不可（2026-04-30 から新規の利用者を受け付けていない） |

- サーバーレスは、EC2 最小 1台に対して、月額で約1/4以下、Fargate に対して約1/5以下の見込み
- 月5,000円の上限に対して、サーバーレスは1割以下で、十分な余裕がある
- 無料枠（Lambda、DynamoDB、Cognito の10,000 MAU、Amplify Hosting のビルド・保存・配信）を使う。Amplify と DynamoDB の無料枠は、期間・条件の情報が食い違うため、アカウントで確認する（TODO）

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|--------|------|------|
| サーバーレス（採用） | 固定費がほぼない。OS・ミドルウェアの管理が不要。冗長性は標準。Cognito で認証を任せられる。Amplify で CI/CD・IaC を得られる。**同じ発注者での実績がある** | 必要な権限が多い（Amplify は複数のサービスを作成する）。ローカルでの再現にエミュレータが要る。接続元IPの固定が必要な場合、固定IPの部品（NAT等）で数千円増え、不利。DBの設計（DynamoDB）が固有。無料枠の期間が不確か |
| Lightsail 1台 | 固定価格で、IP・転送・ストレージ込み。ローカルと同じコンテナで再現できる | OS・コンテナの更新が必要。単一障害点。メモリが小さい（0.5GB）。権限は EC2 とは別に確認が要る |
| EC2 最小 1台 | 必要な権限が基本的。ローカルと同じコンテナで再現できる | 公開IP・ストレージが別料金。OS・コンテナの更新が必要。単一障害点 |
| ECS on Fargate | OS管理が不要で、コンテナのまま運用できる。冗長化しやすい | 常時課金で、サーバーレスより高い。ECS Express Mode は共有のロードバランサを作り、固定費が増える |
| ECS/EKS + RDS・Aurora | 運用が楽。冗長化しやすい | 常時課金。Aurora Serverless v2 は 0 ACU への自動停止に対応するが、画面が約10秒ごとに問い合わせるため停止せず、約6,500円以上になる見込み |
| AWS App Runner | - | **新規の利用者を受け付けていない（メンテナンスモード）**。移行先として ECS Express Mode が案内されている |

## 結果・トレードオフ

- コストが最小で、OS・コンテナの更新が不要になり、運用負荷（NFR-6.1）も小さい。月額が上限の1割以下のため、上限に対する余裕が大きい
- **前提条件の確認が残る**。IAM権限（Amplify、Lambda、DynamoDB、Cognito、EventBridge など）と、ファイルサーバーの接続元IP制限（Q-002）。同じ発注者での実績があれば、権限の確認のリスクは下がるが、今回のIAMユーザーの権限で確認する（TODO）
- DBは DynamoDB 固有の設計になる。期間の集計は、評価の事前計算とアプリ側の集計で成り立つ見込みだが、**機能要件（FR-6.5 の推移のグラフなど）が満たせるか、実装前に検証する**
- Lambda は実行時間に上限があり、起動に遅延（コールドスタート）がある。取り込み・評価は、時間内に終わる単位に分割する。画面の更新（約10秒）への影響は、実測で確認する
- ローカルでの開発・テストは、DynamoDB のローカル版などのエミュレータと、ポートのモック（ADR-0001）で行う
- 稼働率の目標（NFR-4.1。数値が整合しておらず、合意が必要）に対して、マネージドサービスの冗長性を使えるため、1台の構成より有利
- Amplify のデータ層に依存させないことで、ロックインを避ける。移行時は、アダプタの書き換えで対応する
- 規模・要求が増え、コンテナ運用が必要になった場合は、ECS on Fargate へ移行できるよう、論理構成をコンテナ化できる形（ADR-0001）に保つ
- IAMで権限が許されない場合の代替は、architecture.md 11.4 に示す
