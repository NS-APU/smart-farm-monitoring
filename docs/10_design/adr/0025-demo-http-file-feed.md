# ADR-0025 デモの取り込みを、HTTP のファイル配信（Lambda の Function URL）に置き換える（#344）

- ステータス: 承認（2026-11-18。Issue #344）。実装は 3 つの PR に分ける（下の「決定」の 4）。PR 1 は、追加のみ（このADRの 1〜3）。PR 3b（MOCK の接続方式の廃止）まで、実装した。**PR 3 により、[ADR-0012](./0012-demo-data-and-s3-file-server-mock.md) の「ファイルサーバーのモックの S3 版」「合成データの定期生成」は、このADRに置換する**（デモデータの投入・リセットは、ADR-0012 のまま）
- 日付: 2026-11-18
- 更新（2026-11-19。#367）: **接続は、設備ごとに持つ**ことにした（[ADR-0026](./0026-per-equipment-file-server-connection.md)）。デモの取り込み（`demo-data use-http-feed`・`seed --url`）は、デモの設備ごとの接続とファイルのパスだけを設定する（取り込み元の共通の接続は、設定しない。共通の接続は、廃止した）。以下の「取り込み元の接続を HTTP（認証なし）にし」の記述は、この更新で置き換わる。
- 更新（2026-11-25。#298）: **こちらで用意する、ファイルを置ける実際のファイルサーバー**（S3 + Lambda の Function URL。認証つき）は、[ADR-0027](./0027-self-hosted-file-server.md)。このデモ用の配信は、**残す**（開発サイトだけ。置き換えは、#375 で判断する）。
- 関連: [ADR-0012](./0012-demo-data-and-s3-file-server-mock.md)（置換の対象）、[ADR-0013](./0013-environments-and-access-control.md)（本番サイトにデモを作らない）、[ADR-0022](./0022-file-server-http-connection-provisional.md)・[ADR-0023](./0023-http-file-source-per-equipment-file.md)（HTTP の接続・設備ごとのファイルパス）、[security.md](../../20_development/security.md)、Issue #344・#367

目的: ファイルサーバーの接続方式を HTTP に一本化する（#344）にあたり、開発サイト（評価環境）のデモの取り込みを、S3 のモックから、**デモ用の HTTP のファイル配信**に置き換える方法を決める。

## 背景

- 開発サイトのデモデータは、デモ用の Lambda が 15 分ごとに、S3 のバケット（ファイルサーバーのモック。接続方式 MOCK）へ、合成データのファイルを置き、取り込み（JB-01）がそれを読む（ADR-0012）。
- MOCK は、1 つのファイルに複数の設備が入る前提で、設備ごとにファイルを取得する HTTP（ADR-0023）や、設備ごとの接続（#367）と合わない。#344 で、MOCK・S3 のファイルソース・デモ用の S3 とスケジュールを廃止する。そのため、デモも、HTTP のファイルサーバーから取り込む必要がある。
- HTTP のアダプタは、設備の `sourceFilePath` ごとに `HEAD`・`GET` する。Lambda（`APP_MODE=production`）では、内部のアドレスへの接続を拒否する（ADR-0022。`HTTP_FILE_SOURCE_ALLOW_PRIVATE` は、本番の組み立てでは、無効）。そのため、接続先は、**公開の FQDN** が必要。
- 既存のデモの設備には、`sourceFilePath` がない。

## 決定

### 1. デモ用の HTTP 配信は、Lambda の Function URL とする（認証なし）

- **専用の Lambda 関数**（`runtime/demo-feed-http-lambda.ts`）に、Function URL（認証なし。ペイロード形式 2.0）を付ける。**開発サイトだけ**（`includeDemoFeed`）。本番サイトには作らない（ADR-0013）。
- `GET`・`HEAD` で、取り込み元ごとの 1 ファイル（ロボットは `/robot/latest.json`、環境センサーは `/environment-sensor/latest.json`）を返す。内容は、**リクエストごとに**、現在の時刻から作る（`buildDemoFeedFiles`。区間の時刻から決まり、同じ区間は同じ内容。直近 4 区間・15 分刻み）。保管しない（S3・EventBridge・書き込みの権限は、要らない）。
- `Last-Modified` は、現在の区間の開始時刻（その区間に、内容が最後に変わった時刻。「1 つのファイルを随時上書きする」方式〔ADR-0016 の D-08〕と同じ見え方）。`Content-Type: application/json`・`Cache-Control: no-store`。`GET`・`HEAD` 以外は 405（`Allow` を示す）、定めたパス以外は 404。パスの正規化はせず、完全一致だけ。
- **権限は付けない**: S3・DynamoDB・Cognito・秘密情報を使わない（実行ロールの基本の権限〔ログの出力〕だけ）。環境変数も持たない。ログは、30 日で自動削除。
- **認証はしない**。返すのは、合成データだけ（実データ・個人情報・秘密情報は、持たない）。取り込みの接続設定（設備ごと）は、認証方式 `NONE`。呼び出しの量は、取り込みの周期（15 分ごと・設備ごとに `HEAD`・`GET`）だけ。

### 2. デモの設備と、取り込みの設定

- デモの設備（ロボット・環境センサー）の `sourceFilePath`（上のパス。`DEMO_FEED_FILE_PATHS`）は、**下のコマンドが設定する**。`seed`（`SEED_MODE=DEMO` を含む）が作る設備は、ファイルパスを持たない（ローカルのデモ・E2E・MOCK のあいだの動作を、変えないため。「ファイルパスを持つ設備がない」状態を前提にする HTTP の試験が、既にある）。
- **`pnpm demo-data use-http-feed [--url <配信の URL>]`**（環境変数 `DEMO_FEED_URL` でも指定できる）: デモの設備（ロボット・環境センサー）の接続を HTTP（認証なし）にし、`sourceFilePath` を設定する（すでにあれば、そのまま。~~取り込み元の接続~~は、ADR-0026 で廃止）。何度実行しても、同じ。デモの設備がなければ、先に `seed` を実行するよう、エラーにして、何も変えない。`seed` に `--url`（または `DEMO_FEED_URL`）を付けると、投入のあとに、同じことをする。
- URL は、スキーム・ホスト・ポートだけ（パス・クエリ・認証情報は、指定できない。エラーのメッセージにも、含めない）。**接続先は、リポジトリに書かない**: スタックの出力 `DemoFeedUrl` を、運用者が、環境変数・引数で渡す。コマンドの出力にも、接続先を含めない。
- 開発サイト専用（`SFM_ENVIRONMENT=production` では、実行しない）。AWS の操作（デプロイ・コマンドの実行）は、運用者が行う。

### 3. 本番サイト

- 本番サイトには、デモ用の配信を作らない（ADR-0013）。S3 のバケット（空）は、PR 3 で、ほかの MOCK の部品とともに、廃止する。

### 4. 実装の分け方（開発サイトのデモを止めない順序）

| PR | 内容 |
|----|------|
| PR 1（追加のみ。このADRの 1〜3） | デモ用の HTTP 配信（Lambda・Function URL・出力 `DemoFeedUrl`）、`demo-data use-http-feed`・`seed --url`（デモの設備の `sourceFilePath` を設定する）。MOCK・S3・定期生成は、**残す**（動作は変えない）。マージ後に、運用者が、開発サイトで、HTTP のデモの取り込みを確認する |
| PR 2a | 結合テストを、HTTP のテスト用ファイルサーバーに置き換える（共通の補助を作る）。MOCK は、まだ残す。MOCK 専用の観点（ディレクトリがない・60 秒の遅延など）のテストは、MOCK のまま残し、PR 3 で削除する |
| PR 2b | E2E・負荷テストを、HTTP のテスト用ファイルサーバーに置き換える。負荷テストの大量実行は、専用のハウスに、設備（ロボット 20・センサー 10）を追加して、設備ごとに 1 ファイル（1 ファイルの記録数を増やして、処理する記録の総数を保つ。設備の追加は、1 台ごとに評価の更新が走り、台数が多いと時間がかかるため）。MOCK は、まだ残す |
| PR 3a | S3 のバケット・S3 に置くデモ用 Lambda・EventBridge のルール・それらの出力と権限、S3 のファイルソース・バケットを空にする処理、`FILE_SERVER_S3_BUCKET`、依存 `@aws-sdk/client-s3` を削除する（アプリの動作は変わらない。ADR-0012 の「S3 版」「定期生成」を置換する） |
| PR 3b（実装済み） | MOCK の接続方式（ディレクトリのモック `local/mock-file-server.ts`・型・既定・画面の「接続方式」の選択）・開発用 API の `/dev/mocks/file-server`（残るのは federation・web-push）・MOCK 用の分岐・`FILE_SERVER_DIR` を削除する。接続方式は HTTP の 1 つだけ。取り込み元の `connection` は省略可（未設定が既定）で、保存済みの `MOCK` の設定は、読み込むときに未設定に読み替える（移行しない）。接続が未設定の取り込み元は、接続テストが失敗し、一覧は、取得の対象の設備がなければ 0 件・あれば失敗、取得は NOT_FOUND。自動取り込み・即時取得の対象は、ファイルのパスを持つ設備だけ。ローカルでデモ用の配信を 127.0.0.1 で起動するコマンド（`pnpm dev:demo-feed`。既定ポート 8790。`--port`・環境変数 `DEMO_FEED_PORT`）を足す。テストは、HTTP のテスト用ファイルサーバーに一本化し、MOCK 専用のテストは削除する |

## 検討した選択肢

| 選択肢 | 判断 |
|--------|------|
| 既存のデモ用 Lambda（S3 に置く）に、Function URL を足す | 1 つの関数に、S3 の書き込みの権限と、公開の URL が同居する。PR 3 で、S3 側だけを消せない。別の関数にする（権限なし） |
| S3 と CloudFront で公開する | リソース（CloudFront のディストリビューション・オリジンのアクセス制御）が増え、設定が複雑。`Last-Modified`・`HEAD` の扱いを、S3 のオブジェクトの更新時刻に頼ることになり、定期の生成と EventBridge も残る |
| API キーの認証をつける | 秘密情報の作成・保管・ローテーションの手順（運用者の AWS の操作）が増える。返すのは、合成データだけで、得られるものがない。公開の URL への呼び出しが増えたときの、費用の増加が、リスク（下の「結果」） |
| EventBridge で、定期に、ファイルを生成して保管する方式を、HTTP でも残す | 保管先（S3 など）が必要になり、S3 を廃止する目的に反する。リクエストごとに、純関数で作る方が、小さい |
| 配信を作らず、デモは、取り込みの手動の入力だけにする | 開発サイトのデータが古くなり、「データが古い」「不明」になる。取り込みのデモ（UC-08・UC-09）と、評価の更新の確認ができない |

## 結果

- 開発サイトのデモの取り込みを、HTTP（実際のファイルサーバーと同じ手順）で、確認できる。S3 のバケット・EventBridge のルール・書き込みの権限が不要になる（PR 3 で削除）。
- **公開の認証なしの URL が増える**（開発サイトだけ。合成データだけを返す）。呼び出しが急増すると、Lambda の呼び出しの費用が増えるリスクがある（予算に対して、通常の使用は、無料枠の範囲に収まる見込み。**公式の価格・無料枠の再確認は、未実施。実測は未確認**）。対策（同時実行数の上限など）は、必要になったときに、追加する。
- **未確認**: Function URL が、`HEAD` に、`Last-Modified` つきで応答すること（Lambda の手元のハンドラと、手元の HTTP サーバーでは、確認済み。実際の Function URL は、開発サイトで、運用者が確認する。`HEAD` が使えなければ、HTTP のアダプタは、先頭 1 バイトの `GET` に切り替える〔ADR-0022〕）。
- データスキーマの変更: なし（設備の `sourceFilePath` は、ADR-0023 で追加済み）。依存パッケージの追加: なし。IaC: 関数 1 つ・Function URL 1 つ・ロググループ 1 つ・出力 1 つの追加（PR 1）。
- 見直しの条件: #375（シミュレーション）で、デモ用の配信の要否を判断するとき（自前のファイルサーバーは ADR-0027）。デモ用の配信への、想定外の呼び出しが見つかったとき（認証・上限を追加する）。
