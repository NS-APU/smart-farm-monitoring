目的: 宇都宮大学から、ファイルサーバーの接続先・アクセス情報が提供されない可能性が高いため、**こちらでファイルサーバーを用意し**、現地実証で、ロボット（宇都宮大学）が定期的にファイルを置き、本システムが自動で取り込める状態にする。ロボット側の対応が進まない場合は、手動でファイルを配置できる必要がある（秋田県立大学）。費用は、月 5,000 円（NFR-1.3）の目安に対して、**なるべく小さく**する（常時稼働のサーバーは避ける。NFR-1.6・architecture.md 11 章）。

## 背景

- 取り込み（JB-01）は、HTTP のアダプタで、設備ごとの `sourceFilePath` に `HEAD`・`GET` する（ADR-0023）。接続・認証情報（Basic・Bearer・API キー）は、設備ごとに持つ（ADR-0026）。1 設備 = 1 ファイルで、更新のたびに全体が書き換わり、中身は最新の値だけ（データ定義 3 章）。通常 1 MB 以内（本システムが読む上限は 10 MiB）。
- 開発サイトには、デモ用の HTTP 配信（Lambda の Function URL。認証なし・合成データだけ。ADR-0025）がある。リクエストごとに合成データを作って返すだけで、**ファイルを置く口がない**。本番サイトには、ない（ADR-0013）。
- 現地実証は、本番サイトで行う。実際のファイルを置く経路（ロボットの書き込み・手動の配置）と、認証が要る。

## 決定

### 1. 構成: S3 のバケットに、Lambda（Function URL）が、読み書きを仲介する

- **ファイルの保管は、S3 のバケット 1 つ**（非公開。暗号化。SSL 強制。バージョニングなし〔履歴は、取り込みが積み上げる〕）。オブジェクトのキーは、`files` + 設備ごとのファイルパス。
- **専用の Lambda 関数**（`runtime/hosted-file-server-lambda.ts`）に、**Function URL**（URL 自体は認証なし。ペイロード形式 2.0）を付ける。**1 つの URL で、`GET`・`HEAD`・`PUT`** を受ける（ロボットも取り込みも、同じホスト・パスで扱える。普通のファイルサーバーと同じ見え方）。ほかの Lambda（API・ジョブ・デモ配信）とは、別の関数・別の権限。DynamoDB・Cognito は使わない。
- **ロボットは、HTTPS の `PUT` で、設備ごとのパスに、ファイル全体を置く**（認証つき）。S3 の同じキーへの置き換えは、**原子的**で、書き換えの途中のファイルを、読み手に見せない（データ定義 6 章の、望ましい書き換え方式）。
- 本システムの取り込みは、**設備ごとの接続（認証方式: Bearer）で、`GET`・`HEAD`**。`Last-Modified`（S3 の更新時刻）と `ETag` を返す。`Cache-Control: no-store`。ファイルがなければ 404（取り込みは、その設備を一覧に含めない。ADR-0023）。
- **手動の配置**は、同じ `PUT`（書き込み用のトークンを使い、`curl` などで置く）。ブラウザから置く画面・API は、Issue #565 で実装した（上の「更新」）。

### 2. 認証: 読み取り用と書き込み用の 2 種類のトークン（Bearer）

- `Authorization: Bearer <トークン>`。**読み取り用**（`GET`・`HEAD`）と**書き込み用**（`PUT`）を分け、互いの権限には使えない（読み取り用では置けず、書き込み用では読めない）。
- トークンは、**パラメータストア（SecureString）**の `/sfm/<環境>/hosted-file-server/read-token`・`write-token`（SecretPort の参照名 `hosted-file-server/read-token`・`hosted-file-server/write-token`）。**環境ごとに別**の値（開発サイトが、本番サイトのトークンを読めない。ADR-0013）。256 ビット以上のランダムな値。リポジトリ・Issue・PR・ログに書かない。
- 1 つのパラメータに、**カンマで区切って、2 つまで**並べられる（ローテーション中の、新旧の併存）。3 つ目以降は、無効。
- 照合は、定数時間（ダイジェストの比較）で、有効なすべてのトークンと比べる。**トークンが未設定のあいだは、すべて拒否する**（401）。パラメータストアを読めないときは 503（認証の失敗と区別する）。読み出しは、SecretPort の 5 分のキャッシュ。
- 取り込み側は、設備ごとの認証情報（SC-10。書き込み専用の登録。#207）に、**読み取り用のトークン**を登録する。ロボット側には、書き込み用のトークンを渡す。
- 失敗は、固定の文言（`Unauthorized` など）。ファイルの内容・検査の結果を含めない。メソッドの判定（405）は、認証より先。**認証の失敗は、`PUT` の検査（パス・大きさ・JSON）より先**に返す（認証されない相手に、検査の結果を知らせない）。

### 3. `PUT` の検査

- パスは、設備の `sourceFilePath` と同じ規則（`FilePathSchema`。`/` で始まる、ファイル 1 つ。英数字と `. _ ~ ! $ & ' ( ) * + , ; = : @ / -` のみ。`..`・`?`・`#`・空白・`%` は使えない。500 文字以内）。違えば 400。`GET`・`HEAD` で、規則に合わないパスは 404。
- 大きさは、**1 MiB まで**（データ定義の「通常 1 MB 以内」。取り込み側の読む上限 10 MiB より小さい）。超えたら 413。
- 内容は、**UTF-8 の JSON として読めるものだけ**（形式の詳細〔項目・型・値の範囲〕の検査は、取り込み側。ここでは、しない）。空・JSON でない・UTF-8 でない内容は 400。**不正なときは、置かず、すでにあるファイルを残す**。
- 成功は 204。本文は、Lambda の `isBase64Encoded` に対応する。クエリは、解釈しない。`GET`・`HEAD`・`PUT` 以外は 405（`Allow` を示す）。ファイルの一覧は、提供しない（任意のパスを辿らせない。ADR-0023）。
- ログは、結果（メソッド・結果の種別・大きさ）だけ。**トークン・本文・ファイルパス・AWS のエラーの内容は、出さない**（エラーの種類の名前だけ）。

### 4. 権限（IaC は PR 2）

- 実行ロールは、バケットの `s3:GetObject`・`s3:PutObject`・`s3:ListBucket`（`ListBucket` がないと、ファイルがないときに 403 になり、404 を判定できない）と、2 つのトークンの `ssm:GetParameter`・`kms:Decrypt`（パラメータストア経由に限る）だけ。DynamoDB・Cognito・書き込み以外の S3 の操作は、付けない。
- 取り込みの読み取りが「読み取り専用」であることは、**トークンの分離**で守る（読み取り用のトークンでは、`PUT` できない）。関数を、読み取り用と書き込み用に分けると、URL が 2 つになり、ロボット・取り込みの設定が増えるため、1 つの関数にする。

### 5. スタックと環境の分離（IaC は PR 2）

- ファイルサーバーは、**評価環境のスタックとは別の、独立したスタック**にする（開発 `SfmFileServer`・本番 `SfmProductionFileServer`）。理由: Function URL のホストは、関数を作り直すと変わる。ロボット側に設定する URL が、評価環境の再作成・変更に巻き込まれて変わらないようにする（データのスタックを、評価環境と別にしている考え方と同じ）。
- **開発サイトと本番サイトで、バケット・関数・URL・トークンを、別にする**。本番サイトのバケットは、削除の保護（RETAIN）。開発サイトは、削除してよい。
- 既存のデモ用の HTTP 配信（ADR-0025）は、**残す**（開発サイトだけ。置き換えは、#375 で判断する）。

### 6. 費用の上限の対策

- 同時実行数の上限を、関数に付ける（値は、IaC で決める。**アカウントの Lambda の同時実行数の上限が小さいと、設定できないことがある**。開発サイトでは、デプロイが成功し、予約が通った〔2026-11-25〕。本番サイトのデプロイの前に、運用者が確認する）。WAF は、使わない（固定費が出るため）。AWS Budgets などの自動の監視は、設けない（architecture.md 11.1）。
- 認証に失敗するリクエストも、呼び出しの費用はかかる。トークンが 256 ビットで、推測できないことと、同時実行数の上限で、費用の増加を抑える。

### 7. 取り込み・データ定義との関係

- ファイルの形式・構造・更新の頻度の仮定は、[robot-data-definition.md](../data/robot-data-definition.md)・[environment-sensor-data-definition.md](../data/environment-sensor-data-definition.md) のとおり（変えない）。
- **ファイルのパスの規約（運用）**: `/<種別>/<設備を表す名前>/latest.json`（種別は `robot`・`environment-sensor`）。設備の `sourceFilePath` と、1 対 1。サーバーは、この規約を強制しない（`FilePathSchema` だけ。規約は、運用手順に書く）。
- 実データ用の設備は、合成データの設備と、別に作る（別の設備 ID・別のパス。ADR-0021）。本番サイトは、合成データの配信を持たない（ADR-0013）。

### 8. 依存パッケージ

- `@aws-sdk/client-s3`（Apache-2.0）を、バックエンドに再追加する（#344 で削除した）。Lambda のバンドルにだけ入る。版は、ほかの AWS SDK と同じ系列。

## 結果

- ロボットが、HTTPS の `PUT` で、設備ごとのファイルを置き、取り込みが、既存の HTTP・Bearer の仕組みで、自動で読める。手動の配置も、同じ `PUT` でできる。
- 費用は、約 50 円/月（1 環境）の見込み（仮定。**実測は未確認**。運用を始めて 1 か月後に、AWS のコスト管理で実測する。operations.md 8.11。公式の価格・無料枠は、デプロイの前に、再確認していない）。常時課金の部品を持たない。
- **公開の URL が増える**（トークンで保護する）。トークンの漏えい（書き込み用）は、ファイルの改ざんにつながる。ローテーション（2 つ併存）と、環境ごとの分離で、影響を小さくする。呼び出しの急増による費用の増加のリスクは、同時実行数の上限で抑える（未確認の前提あり）。
- データスキーマの変更: なし。依存パッケージの追加: `@aws-sdk/client-s3`。IaC: PR 2 で、独立したスタックの追加。
- **確認結果（2026-11-25。開発サイト。ユーザーの報告）**: デプロイは成功し、同時実行数の予約が通った。operations.md 8.11 の確認は、すべて想定どおりだった（実際の S3・Function URL の動作〔`HEAD` の `Last-Modified`・ファイルなしの 404〕を含む。取り込みの接続テスト・即時取得も含む）。
- **未確認**: ロボット（宇都宮大学）が、HTTPS の `PUT`（Bearer のヘッダー）に対応できるか。費用の実測。本番サイトでの確認（実証の前に、8.11 を読み替えて行う。現地訪問のチェックリスト: [field-visit-checklist.md](../../40_operations/field-visit-checklist.md)）。
- 見直しの条件: ロボットが `PUT` に対応できないと分かったとき（rsync・SFTP の受け口を、別に用意する。上の表の Lightsail など）。宇都宮大学のファイルサーバーの接続先・アクセス情報が、提供されたとき（取り込み元の切り替えは、別の Issue）。
