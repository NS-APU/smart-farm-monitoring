# ADR-0020 認証の規則（ログインの制限・パスワード）を、恒久の仕様にする（#147 の決定）

- ステータス: 承認（2026-10-26。ユーザーの判断。Issue #147）
- 日付: 2026-10-26
- 関連: [ADR-0008](./0008-cognito-authentication.md)、[ADR-0010](./0010-client-ip-from-cloudfront-function.md)、[ADR-0013](./0013-environments-and-access-control.md)、[ADR-0019](./0019-notification-rules.md)、FR-9.1〜FR-9.7、UC-13・UC-14、[security.md](../../20_development/security.md)

目的: 認証の、暫定だった規則（ログイン試行の制限の値・アカウント単位のロック・パスワードの変更・再設定）を、決めて、恒久の仕様にする。決めた経緯（背景・見直しの条件）は、各決定のコメント（#147）にもある。ロール・権限（D-43）と、「運用者」「管理者」の区別（D-50）は、ADR-0013 で決定済みで、文書の整理は #149 で行う。

## 背景

- ログインの試行の制限は、構想時の値（同一の接続元から 15 分あたり 5 回まで）で、コードの定数だった。アカウント単位の一時ロックは、発注者の確認待ち（Q-017）だった。
- パスワードは、管理者が決めて入力する。Cognito では、永続のパスワードとして設定するため、**管理者が、利用者のパスワードを知っている**状態だった。本人が変える機能は、未実装（#115）。
- IP 制限・WAF は、設けない（ADR-0013。費用・利用者 10 名ほど）。ログインの総当たりへの防御は、接続元ごとの制限と、Cognito のユーザーごとのロックだけ。

## 決定

### D-44 ログイン試行の制限

- **接続元ごとの制限**: 失敗 **5 回 / 15 分**（構想時の値を恒久化）を、**設定値（環境変数）**にして、運用で調整できるようにする。誤ってロックされる事例（共有の IP。回線は、ローカル 5G が基本）が出たときに、コードの変更なしで、回数・時間を変えられる。
- **アカウント単位の一時ロック**: **アプリでは持たず、Cognito のユーザーごとのロックに任せる**。ロックは、時間で自動的に解除される（管理者の解除操作は、設けない）。ローカル実行（Cognito なし）は、接続元ごとの制限だけ（開発・検証用）。誰かの ID を知る攻撃者が、わざとロックして、本人を締め出せるため、アプリでは二重に持たない。
- **パスワードの条件・失敗の表示**: 現状を恒久化する。パスワードは、8 文字以上で、英大文字・英小文字・数字を含む（Cognito のポリシー）。ログインの失敗の表示は、ユーザー ID の有無を区別しない。
- 見直しの条件: 共有の IP で、誤ロックが起きたとき（回数を緩める）。

### D-45 パスワードの変更・再設定

- **管理者が、登録・再設定で決めたパスワードは、「一時」のもの**とする。**本人が、最初のログインで、新しいパスワードを決めるまで、ほかの操作ができない**。管理者は、本人が決めたパスワードを、知らない。実現は、ユーザーの記録に「パスワードの変更が必要」の印を持たせる方式（ローカルと Cognito で、同じ動き）。
- **本人によるパスワード変更**（#115。FR-9.7）は、**現在のパスワードの入力を求める**。新しいパスワードは、現行の条件と同じ。変更すると、**他の端末のセッションは失効**する。ユーザー ID・ロールは、変えられない。
- **忘れたとき**は、**管理者が再設定**する（現状）。再設定したパスワードも、一時のもの。メールによる本人の再設定は、設けない（メールアドレス〔個人情報〕の登録と、SES の設定が要り、メールを見送った方針〔ADR-0019 の D-36〕と合わない）。
- **管理者は、2 名以上にする**ことを、運用の前提とする（管理者が 1 人だけで、パスワードを忘れると、アプリからは復旧できず、AWS の管理者の操作が要る）。
- パスワードの**有効期限・履歴は、設けない**（定期的な変更は、求めない）。
- 見直しの条件: 利用者が増え、管理者の再設定が負担になったとき（本人による再設定を検討する）。

## 結果・トレードオフ

- 認証の規則が、決まり、文書の TODO が置き換わる。実装は、別の Issue（下記）。決定のうち、実装が済んでいないものは、文書に「決定（実装は #xxx）」と書いて、現状と区別する。
- 接続元ごとの制限は、共有の IP で、利用者が互いにロックされうる。設定値で緩められる。接続元の偽装による回避（#102）は、残る。
- 忘れたときの再設定は、管理者に依存する。管理者が不在のときは、再設定できない。
