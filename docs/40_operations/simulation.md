# シミュレーション（一日を通して変化するデータの投入）

実機・実データがなくても、ロボットと環境センサーの「一日の動き」を、ロボットと同じ `PUT` で、ファイルサーバーに置いて、取り込み・評価・ダッシュボード・通知の動きを、通して確かめるためのコマンド（`pnpm simulate`）と、その手順。Issue #375。ADR-0027（自前のファイルサーバー）の続き。

- **置くのは、合成データだけ**（実際の機体・作物の値ではない。仮定）。実データ・個人情報は、使わない
- **置き先は、ローカルのファイルサーバー（`pnpm dev:file-server`）、または、開発サイトの自前のファイルサーバー**。**本番サイトには、置けない作りにしている**（次の「安全のための制限」）
- 操作する人: 開発者・検証する人。**AWS・開発サイトの操作と、トークンの扱いは、ユーザーが行う**（AI エージェントは、実行しない。AGENTS.md 12 章）

## 安全のための制限

実際の設備・本番のデータを、壊さないための制限。コマンドの側で、守る（破れない）。

| 制限 | 内容 |
|------|------|
| 置けるパス | `/robot/sim-<名前>/<ファイル名>.json`（ロボット）・`/environment-sensor/sim-<名前>/<ファイル名>.json`（環境センサー）だけ。`<名前>` は、英小文字・数字・ハイフン。**`sim-` で始まらないパス（実際の設備のパス）には、置けない** |
| 置き先 | ローカル（`127.0.0.1`・`localhost`・`[::1]`）は、そのまま。**それ以外は、`https` の URL と、`--target development` の指定が必要**。`--target` に指定できるのは、`development` だけ（**本番は、指定できない**） |
| トークン | 書き込み用のトークンは、**環境変数 `SIM_WRITE_TOKEN` だけ**で渡す（引数・出力・状態ファイルに出さない）。ローカルは、指定がなければ、ダミーのトークン（`pnpm dev:file-server` と同じ）を使う |
| URL | スキーム・ホスト（・ポート）だけ。認証情報・パス・クエリは、含められない。**コマンドの出力に、URL（ホスト名）は、出さない** |

開発サイトで使うときも、**本番サイトの URL・トークンを、指定しない**（本番の書き込み用のトークンは、別の値。8.11）。

## 標準シナリオ（`standard-day`）

日本時間の一日（00:00〜24:00）を、シナリオの時刻として進める。ロボットは、2 台（1 台目だけ、13:00 台に異常が起きる）。環境センサーは、1 台。値は、設備ごとに、少しずつ違う（収穫の速さ ±10%、温度 ±0.6℃。同じ指定なら、同じ値になる）。

| シナリオの時刻 | ロボット（全台） | 1 台目だけ | 環境センサー |
|----------------|------------------|------------|--------------|
| 00:00〜06:00 | 電源なし（待機のコード・値はすべて 0） | | 夜（温度 14〜15℃・照度 0） |
| 06:00〜06:30 | 稼働（RUNNING） | | 日の出（照度が上がる） |
| 06:30〜11:00 | 収穫（HARVESTING）。600 個/時・42 秒/個 | | 温度 18→27℃ |
| 11:00〜11:30 | 待機（STANDBY） | | |
| 11:30〜13:30 | 収穫。540 個/時・45 秒/個 | 13:00〜13:10 収穫異常（HARVEST_ERROR）→ 13:10〜13:30 停止中（STOPPED）。収穫数は増えない | 昼の高温: 12:30 に 30℃（**注意**）→ 13:20 前後に 36.5℃（**異常**。35℃ 以上） |
| 13:30〜16:00 | 収穫。480 個/時・52 秒/個 | | 36℃ → 28℃ |
| 16:00〜17:30 | 収穫。440 個/時・58 秒/個 | 16:00〜16:20 バッテリー不足（LOW_BATTERY） | 夕方に下がる |
| 17:30〜18:00 | 待機 | | 日没（照度が 0 へ） |
| 18:00〜24:00 | 電源なし | | 夜（温度 24→16℃） |

- **累積の項目**（収穫数・稼働時間・待機時間・収穫稼働時間・走行停止時間。収穫数は整数）は、日本時間の 0 時に、0 に戻る（ロボットの累積値の扱い。D-26）。一日のうちは、減らない
- 温度以外の値（湿度・照度・CO2）は、昼間は、環境適応性の判断基準の「正常」の範囲に収めてある。**高温だけが、評価を変える**（昼の 30℃ で「注意」、13:20 前後に「異常」）。夜間は、照度が 0 のため、現行の判断基準（照度の正常範囲 20,000〜40,000 lx）では、範囲外になる
- ステータスコードは、初期の登録値（データ辞書 7 章）。値の出どころは、すべて仮定（実際の機体・作物の値は、確認していない）

## 時間の進め方（計測日時と、値）

- **計測日時（`timestamp`）は、置いた時刻（実際の時計）**。値は、**シナリオの時刻**（日本時間の一日）に従う。計測日時を、シナリオの時刻にしないのは、取り込みが、未来（5 分を超える）・遅延（60 分を超える）の計測日時を、不正・遅延として扱うため
- **倍速（`--speed`）**: シナリオの時間が、実際の時間の何倍で進むか。**置く間隔（`--tick`。実際の秒）**ごとに、シナリオの時刻が `tick × speed ÷ 60` 分進む。既定は、倍速 60・10 秒ごと（1 回で、シナリオの 10 分。一日分が、約 24 分）
- **取り込みは、最新のファイルだけを読む**（設備ごとの取得間隔。既定はロボット 1 分・センサー 5 分）。1 回で進むシナリオの時間（上の `tick × speed ÷ 60` 分）が、**取得間隔より長い**と、途中の状態（たとえば、10 分の異常）が、取り込みに見えない。**異常のような短い状態まで見るには、倍速を下げる**（例: 倍速 10・60 秒ごと = 1 回で 10 分、実際の 1 分。取得間隔 1 分のロボットが、すべての回を拾う）
- シナリオの一日分を、実際の時間で流すと長いため、途中で止めて（Ctrl+C）、`--resume` で続けられる

## コマンド

```powershell
pnpm dev:file-server        # ローカルのファイルサーバー（127.0.0.1:8791。メモリ。ダミーのトークン）
pnpm simulate --url <URL>   # シミュレーションを流す
```

`pnpm simulate` の指定:

| 指定 | 内容 | 既定 |
|------|------|------|
| `--url <URL>`（または環境変数 `SIM_FILE_SERVER_URL`） | 置き先のファイルサーバー（必須。スキーム・ホスト・ポートだけ） | なし |
| `--robot <パス>`（繰り返し可） | ロボットのファイルのパス。指定した順番が、設備の番号（1 台目・2 台目）。指定すると、既定を置き換える | `/robot/sim-robot-1/latest.json`・`/robot/sim-robot-2/latest.json` |
| `--sensor <パス>`（繰り返し可） | 環境センサーのファイルのパス | `/environment-sensor/sim-sensor-1/latest.json` |
| `--scenario <名前または JSON>` | `standard-day`（内蔵）、または、シナリオの JSON ファイル（`.json`）のパス | `standard-day` |
| `--speed <N>` | 倍速（0.01〜86400） | 60 |
| `--tick <秒>` | 置く間隔（実際の秒。1〜3600） | 10 |
| `--start-at <HH:MM>` | 開始のシナリオの時刻 | 00:00 |
| `--days <N>` | 何日分（1〜30） | 1 |
| `--resume` | 状態ファイルの続きから（時刻・累積を引き継ぐ。ファイルがなければ、最初から。終了の時刻は、最初の指定のまま） | 最初から |
| `--state-file <パス>` | 状態ファイルの場所（秘密情報・接続先は、含まない） | `.local-data/simulation-state.json`（Git の管理外） |
| `--target development` | ローカル以外（開発サイト）へ置くときに必須 | なし |
| `--dry-run` | 置かずに、流れだけを確かめる（状態ファイルも書かない） | 置く |

- 環境変数: `SIM_WRITE_TOKEN`（書き込み用のトークン。ローカル以外は必須）。**値を、チャット・Issue・PR・ログ・コミットに書かない**
- 終了コード: 0（完了・中断）、1（指定の誤り・続けられない失敗）。認証・内容の誤り（HTTP 401・403・400・413 など）は、すぐに止める。一時的な失敗（HTTP 500 台・通信の失敗など）は、数えて続け、**すべての置く操作が、5 回続けて失敗**したら、止める
- Ctrl+C で、次の回の前に止まる。状態は、各回のあとに保存している（`--resume` で続ける）

## 自分のシナリオ（JSON）

`--scenario my.json` で、別の一日を使える。形は、標準シナリオ（`src/backend/application/simulation/standard-day.ts`）と同じ。

```json
{
  "name": "my-scenario",
  "description": "説明（500 文字まで）",
  "robot": [
    { "from": "00:00", "to": "08:00", "status": "STANDBY", "activity": "off" },
    { "from": "08:00", "to": "20:00", "status": "HARVESTING", "activity": "harvesting", "harvestPerHour": 500, "secondsPerFruit": 45 },
    { "from": "20:00", "to": "24:00", "status": "STANDBY", "activity": "off" },
    { "from": "10:00", "to": "10:30", "status": "STOPPED", "activity": "stopped", "equipment": [2] }
  ],
  "sensor": {
    "temperature": [{ "at": "00:00", "value": 18 }, { "at": "12:00", "value": 28 }, { "at": "24:00", "value": 18 }],
    "humidity": [{ "at": "00:00", "value": 70 }, { "at": "24:00", "value": 70 }],
    "illuminance": [{ "at": "00:00", "value": 0 }, { "at": "12:00", "value": 30000 }, { "at": "24:00", "value": 0 }],
    "co2": [{ "at": "00:00", "value": 900 }, { "at": "24:00", "value": 900 }]
  }
}
```

- `name`: 英小文字・数字・ハイフン（64 文字まで）。`description`: 必須
- `robot`: 時間帯（`from`〜`to`。`HH:MM`。`to` は 24:00 まで）。`status` は、登録済みのステータスコードのコード値。`activity` は、`off`（電源なし。累積は増えない）・`standby`（稼働・待機が増える）・`running`（稼働が増える）・`harvesting`（収穫・稼働・収穫稼働が増える。`harvestPerHour` の速さで収穫数が増える。`secondsPerFruit` を出す）・`stopped`（稼働・走行停止が増える）。**`equipment` を指定しない時間帯は、一日（00:00〜24:00）を、隙間なく、重ならないように覆う**。`equipment`（設備の番号。1 から）を指定した時間帯は、その設備だけ、全台向けの時間帯より優先する（限定した時間帯どうしは、重ならない）
- `sensor`: 項目ごとに、時刻と値の点（2 つ以上。時刻の昇順）。点の間は、直線で補う。範囲は、データ定義のとおり（温度 -50〜100・湿度 0〜100・照度 0〜200,000・CO2 0〜10,000）
- 誤りは、`pnpm simulate` の起動時に、項目の位置つきで示す（値は、示さない）

## 手順 1: ローカルで試す（ユーザーまたは開発者が実行）

AWS・開発サイトは、使わない。手元だけで、置く → 取り込み → 評価 → ダッシュボードまでを確かめる。

| 手順 | 操作 | 期待する結果 |
|------|------|--------------|
| A（ファイルサーバーの起動） | ターミナル 1 で `pnpm dev:file-server` を実行する | 「ローカルのファイルサーバーを起動しました」と、ダミーのトークン（読み取り用・書き込み用）・設定の案内が出る。ポート 8791 が使われているときは、`--port <番号>` で別のポートにする |

| C（設備の登録） | メニューの「ハウス・設備」画面で、ロボット 2 台・環境センサー 1 台を登録する。ファイルパスは、既定の `/robot/sim-robot-1/latest.json`・`/robot/sim-robot-2/latest.json`・`/environment-sensor/sim-sensor-1/latest.json`。登録したダイアログの「取り込み元の接続」で、プロトコル HTTP・ホスト 127.0.0.1・ポート 8791・認証方式「Bearer トークン」にして保存し、もう一度ダイアログを開いて、認証情報に、手順 A の画面に出た**読み取り用**のトークンを登録する（3 台とも） | 「認証情報を保存しました」。メニューの「取り込み」画面の設備ごとの表に、接続が出る |
| D（流す） | ターミナル 4 で `pnpm simulate --url http://127.0.0.1:8791/ --start-at 12:00 --speed 10 --tick 60` を実行する | 「シミュレーションを始めます」のあと、1 分ごとに `[1 日目 12:00] 置きました 3/3（sim-robot-1: HARVESTING、…）` のように出る（シナリオの 12:00 から、1 回で 10 分ずつ進む） |

| F（評価・通知の確認） | シナリオの 13:00 を過ぎる（約 6 分後）まで待ち、メニューの「ダッシュボード」画面と、通知を見る | 環境センサーの環境適応性が、昼に「注意」、13:20 前後に「異常」になり、1 台目のロボットの収穫速度が、13:00 台の停止のあと「異常」になり、それぞれ通知（状態の変化）が出る（結合テストでは、12:30 に「注意」、13:40 に「異常」を確認した）。評価は、5 分ごとのため、反映まで最長 5 分かかる |
| G（中断・再開） | ターミナル 4 で Ctrl+C を押す → 「中断しました」。同じ指定に `--resume` を付けて、もう一度実行する | 「状態ファイルの続きから始めます」。収穫数などの累積が、途切れずに続く |
| H（後片付け） | ターミナル 1・4 を Ctrl+C で止める。必要なら、`.local-data/simulation-state.json` を削除する。登録した設備は、「ハウス・設備」画面で削除する | ローカルのファイルサーバーのファイルは、停止で消える |

## 手順 2: 開発サイトで試す（ユーザーが実行）

**開発サイトの自前のファイルサーバー（8.11）に置く。本番サイトには、置かない。** サーバーの URL（ホスト名）・トークンの値は、チャット・Issue・PR・ログ・コミットに書かない。

**前提**: 8.11 の確認が済み、開発サイトに、自前のファイルサーバー（スタック `SfmFileServer`）と、読み取り用・書き込み用のトークンの登録（8.11 の手順 B・C）がある。8.11 の後片付け（手順 I）で、一時のトークンのファイルを消している場合は、トークンを作り直して、上書きで登録する（開発サイトの、ロボット側に渡す前の値は、作り直してよい。反映は最長 5 分）。シミュレーション用の設備は、**実際の設備・デモの設備と別**にする（設備 ID・名称・パス。ADR-0021）。実データの設備に、`sim-` のパスは、使わない。

|------|------|--------------|
| A（設備の登録） | 開発サイトに、管理者でログインし、メニューの「ハウス・設備」画面で、名称に「シミュレーション」と分かる名前を付けて、ロボット 2 台・環境センサー 1 台を登録する。ファイルパスは、`/robot/sim-robot-1/latest.json`・`/robot/sim-robot-2/latest.json`・`/environment-sensor/sim-sensor-1/latest.json`。登録したダイアログの「取り込み元の接続」を、プロトコル HTTPS・ホストは 8.11 の手順 A の URL のホスト・ポートは空・認証方式「Bearer トークン」にして保存し、もう一度開いて、認証情報に、**読み取り用**のトークンを登録する（3 台とも） | 「認証情報を保存しました」。メニューの「取り込み」画面の設備ごとの表に、3 台の接続が出る。「接続テスト」は「ファイルが見つかりません」（まだ置いていない。接続・認証は成功） |

| D（本番へ置けないことの確認。任意） | 次のコマンドが、**エラーで止まる**ことを確かめる: `pnpm simulate --target production` ／ `pnpm simulate --robot /robot/robot-a/latest.json` ／ `--target` を付けずに、`SIM_FILE_SERVER_URL` だけで実行 | それぞれ「`--target` には、development だけを指定できます」・「シミュレーション専用のパスだけ」・「`--target development` の指定が必要です」と出る（置かない） |

## 合成データの定期生成（デモ用の配信）との関係

- デモ用の配信（`pnpm dev:demo-feed`・開発サイトのデモ用の配信。ADR-0025）は、**現在の時刻から、リクエストごとに合成データを作って返す**配信で、`/robot/latest.json`・`/environment-sensor/latest.json` を返す。**置かれたファイルを読む、自前のファイルサーバー**（`pnpm dev:file-server`・開発サイトの `SfmFileServer`。ADR-0027）とは、**別の仕組み**
- シミュレーションが置くのは、自前のファイルサーバーの、`sim-` で始まるパスだけ。デモ用の配信のパス（`/robot/latest.json` など）・デモの設備・実際の設備には、置かない（置けない）。**同じ設備に、両方を設定しない**（1 設備 = 1 ファイル = 1 つの接続。ADR-0023・ADR-0026）。両方を使うときは、設備を分ける
- 併用してよい: デモの設備は、デモ用の配信、シミュレーション用の設備は、自前のファイルサーバー（別の設備・別の接続）。評価は、設備ごとのため、混ざらない
- 置き換えない: デモ用の配信は、設備を登録せずに、動く画面を見るための仕組み。シミュレーションは、設備・接続を登録して、取り込みの経路（`PUT` → ファイルサーバー → 取り込み）まで確かめる仕組み。使い分ける

## 失敗したとき

| 出力 | 原因と対応 |
|------|------------|
| 「`--url`（または環境変数 SIM_FILE_SERVER_URL）に…」 | 置き先の URL が指定されていない |
| 「ローカル以外（開発サイト）へ置くには、`--target development` の指定が必要です」 | ローカル以外の URL に、`--target development` を付けていない（**本番は、置けない**） |
| 「ローカル以外の接続先は、https の URL だけ…」 | 開発サイトの URL は、`https://` で始まる |
| 「書き込み用のトークンを、環境変数 SIM_WRITE_TOKEN に設定してください」 | ローカル以外は、環境変数が必須 |
| 「`--robot` のパスは、`/robot/sim-<名前>/…`」 | シミュレーション専用のパス（`sim-`）だけ。実際の設備のパスには、置けない |
| 「シミュレーションを止めました: HTTP 401」 | 書き込み用のトークンが違う（読み取り用を指定していないか。8.11 の手順 C のパス・環境・前後の空白） |
| 「…: HTTP 400」 | 置いた内容が、サーバーに拒否された（JSON でない・パスの規則に合わない）。シナリオの JSON・パスを確認する |
| 「…: すべて失敗した」 | 通信できない（URL・ネットワーク・サーバーの障害）。ローカルは、`pnpm dev:file-server` が起動しているか確認する |
| 「状態ファイルが、今回の指定（シナリオ・設備）と合いません」 | `--resume` の状態ファイルが、別のシナリオ・設備のもの。`--resume` を外す（最初から）か、`--state-file` を変える |
| 取り込みが「ファイルが見つかりません」 | まだ置いていない、または、設備のファイルパスが、置いたパスと違う（「ハウス・設備」画面の設備のダイアログで確認） |
| 取り込みが、日時の問題で、「不正」・「遅延」になる | 計測日時は、置いた時刻。コマンドを動かす端末の時計が、大きくずれていないか確認する |
