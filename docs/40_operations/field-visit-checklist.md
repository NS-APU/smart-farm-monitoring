# 現地訪問（実証実験）の確認・設定項目のチェックリスト

目的: 実証実験の現地訪問（宇都宮大学の圃場）で、ロボットのデータを、自動で取り込める状態にするために、**訪問の前に済ませること・現地で確認すること・訪問のあとにすること**を、一覧にする。自動で取り込む経路は、こちらで用意したファイルサーバー（S3 + Lambda の Function URL。[ADR-0027](../10_design/adr/0027-self-hosted-file-server.md)。手順は [operations.md](./operations.md) 8.11）で、**ロボットが、HTTPS の `PUT` で、設備ごとのファイルを置く**。ロボット側の対応が進まない場合は、手動でファイルを置く（秋田県立大学）。

使い方: 項目ごとに、確認した日と結果を、Issue #298 のコメント（または、現地の記録）に書く。**接続先（ホスト名）・トークン・アカウント ID・担当者の個人情報は、リポジトリ・Issue・PR・チャットに書かない**（書き込み用のトークンを、ロボット側へ渡す方法は、値を文書に残さない方法で、訪問の前に決める）。確認できなかった項目は、その旨を残す。

## A. 訪問の前（本番サイトの準備）

- [ ] **本番サイトの、ファイルサーバーのデプロイ**: 本番サイトに、`SfmProductionFileServer` を作る（`main` へのマージ。operations.md 9.3）。**デプロイの前に、アカウントの Lambda の同時実行数の上限を確認する**（8.11 の前提。予約が通らないと、デプロイが失敗する）
- [ ] **本番用のトークンの生成・登録**（8.11 の手順 B・C。パスは `/sfm/production/hosted-file-server/…`）。**開発サイトの値を使い回さない**。読み取り用・書き込み用は、別の値
- [ ] **本番サイトで、8.11 の手順（E〜H）を読み替えて確認する**（接続テスト・`PUT`・取り込み・権限と検査の確認）。確認用の設備・ファイルは、確認のあとに削除する（手順 I）
- [ ] **実データを入れる条件の確認**（operations.md 9.8・[ADR-0013](../10_design/adr/0013-environments-and-access-control.md) 6 章・[ADR-0021](../10_design/adr/0021-nonfunctional-ops-doc-rules.md)）: 個人情報は入れない／ユーザー名・ID は匿名の識別子／最初は管理者だけ／バックアップ（PITR・開始前のオンデマンド）。本番サイトの独自のサブドメイン・HTTPS（#341）が済んでいること
- [ ] **実データ用の設備の登録**（本番。SC-10）: ハウス・ロボット（・環境センサー）。**合成データの設備と、別にする**（別の設備 ID・別のファイルパス。ADR-0021）。設備のデータ上の識別子（`externalId`）は、匿名にする
  - [ ] ファイルパスを、規約 `/<種別>/<設備を表す名前>/latest.json`（種別は `robot`・`environment-sensor`）で設定する。**設備ごとに、重複させない**（機体が複数あるときは、機体ごとにファイルを分ける）
  - [ ] 取り込み元の接続: プロトコル HTTPS・ホスト（本番の `HostedFileServerUrl` のホスト）・認証方式 Bearer・認証情報（読み取り用のトークン）
  - [ ] 取得間隔: ロボット 1 分・環境センサー 5 分（既定。ロボットの更新頻度に合わせる。データ定義の運用の仮定）。「自動取り込みを有効にする」を確認する
- [ ] **ロボット側に伝える情報を、まとめておく**（値は、文書に残さず、安全な方法で渡す）:
  - 置く先: HTTPS の URL（ホスト）と、設備ごとのパス
  - 置き方: `PUT`・ファイル全体を、毎回、上書き・`Authorization: Bearer <書き込み用のトークン>`・`Content-Type: application/json`
  - 置けるファイル: UTF-8 の JSON・**1 MiB まで**・**JSON として読めないと拒否される**（400。既存のファイルは残る）
  - ファイルの形式: [ロボットのデータ定義](../10_design/data/robot-data-definition.md)（`robot-json` 1.0.0。7 項目・その時点のスナップショット 1 つ・設備の識別子はファイルの中に持たない）／[環境センサーのデータ定義](../10_design/data/environment-sensor-data-definition.md)
  - 応答: 成功は 204。`401` はトークンの誤り、`400` は JSON・パスの誤り、`413` は大きさの超過、`503` は一時的な障害（再試行する）、`429` は呼び出しの制限（間隔をあける）
- [ ] **手動で置く備え**: 手順（8.11 の手順 F の `curl` の例）を、担当者が使える状態にする。ブラウザから置く画面は、SC-11 の設備の行の「ファイルを置く」（#565。管理者。検査してから置く。手順は operations.md 8.12）
- [ ] 現地の**通信環境の確認**: ロボット（または現地の機器）から、インターネットへ HTTPS（443）で出られるか（プロキシ・通信の制限・証明書の検査〔TLS の中継〕の有無）。機器が、TLS 1.2 以上と、一般の認証局の証明書の検証に対応しているか（`PUT` の宛先は、AWS の Function URL の証明書）。機器の時計が正しいか（計測日時の基準）
- [ ] 本番サイトの通知（Web Push）の準備: 実機での受信の確認は、設備の登録のあとに行う（operations.md 8.6 の本番の読み替え。#241）

## B. 現地での確認（ロボット側）

- [ ] **ロボットが、HTTPS の `PUT`（`Authorization: Bearer` のヘッダー）で、ファイルを置けるか**（**最重要。これまで未確認**）。置けない場合の代替: 手動で置く（秋田県立大学）、または、別の受け口（rsync・SFTP など）を用意する（ADR-0027 の見直しの条件。常時課金・運用の手間が増える）
- [ ] 実際に置いて、応答が `204` になること。失敗の応答（401・400・413・503・429）を、ロボット側で確認できるか（ログ・表示）
- [ ] **置く頻度**（本システムの取得間隔の既定は、ロボット 1 分。ロボットの更新のほうが遅ければ、新しい値がない周期は何もしない。速ければ、取得の間の値は取り込まれない）
- [ ] **書き換えの方法**: ファイル全体を、毎回、上書きできるか（S3 の置き換えは原子的で、書き換えの途中のファイルは見えない）
- [ ] **ファイルの中身**（ロボットのデータ定義 8 章の「確認したい点」を持参する）: 累積の基準（今日の分・電源投入後・通算）／時間の単位／ステータスコードの一覧／7 項目が出力できるか（収穫数の意味を含む）／ファイルの形式・構造／計測日時（タイムゾーン）／欠損の表し方（`null`）／機体ごとのファイル分割／手動入力で補う項目
- [ ] **環境センサー**（用意する場合）: 機種・取得方式・ファイルの形式（[環境センサーのデータ定義](../10_design/data/environment-sensor-data-definition.md) 6 章の確認したい点）
- [ ] 食い違いがあれば、データ定義との差分を洗い出し、版を上げる方針を決める（データ定義 9 章）

## C. 現地での確認（本システム側）

- [ ] SC-11 で、「接続テスト」が成功する（ファイルが、まだ置かれていなければ、「ファイルが見つかりません」が正常）
- [ ] ロボットが置いたファイルを、「即時取得」で取り込める（取り込みログに成功。ファイル 1 件）。同じ内容を続けて取り込まない
- [ ] 自動の取り込みが、取得間隔ごとに動く。ダッシュボード・設備の詳細に、新しい値が反映される（画面は、10 秒ごとに自動で更新する）
- [ ] 評価（健全性）が、取り込んだ値で更新される（「データが古い」にならない）。ロボットの更新を止めたとき（または、ファイルを置かないとき）の表示（「データが古い」など）を確認する
- [ ] 本番サイトの通知（Web Push）が、実機に届く（設備の登録のあと。operations.md 8.6）
- [ ] 取り込めないときの切り分け: 401（トークン）・404（パスの食い違い）・400（JSON）・413・503・429（operations.md 8.11 の「失敗したときの見方」・8.5）。ログの確認（8.11 の「ログの見方」）

## D. 訪問のあと

- [ ] **トークンのローテーション**（現地で、書き込み用のトークンを共有した場合・漏えいの疑いがある場合。8.11）
- [ ] **実データの扱い**: 結合確認ごとに、期間を決め、確認が終わったら、すみやかに実データを削除する（ADR-0021。設備の削除。operations.md 9.7）。個人情報が含まれないことの確認
- [ ] 確認の結果を、Issue のコメントに記録する（成功・失敗・期待と違った点・ロボット側の対応の可否。接続先・トークンを含めない）。必要なら、データ定義・ADR・設計書を更新する
- [ ] 費用の実測（運用を始めて 1 か月後。AWS のコスト管理で S3・Lambda を確認。8.11 の費用。見積もりは、月 約 50 円の仮定）
- [ ] 宇都宮大学の接続先・アクセス情報が、のちに提供された場合: 取り込み元の切り替えは、別の Issue で扱う（ADR-0023・ADR-0027）
