## 3. 今回見つかった不具合と修正

### 3.1 失敗の内容（再現）

- 追加した画面の検査 E2E は、修正前に、**当時の 9 件（各幅の「無効→有効→解除」「未対応・許可なしの案内」「宛先が上限」）が、すべて失敗**した（その後、未対応と許可なしを別のテストに分け、12 件にした）。内容は「`form-actions` と `muted`（続く案内文）の隙間 = 0」「`form-actions` と `form-success`（完了の表示）の隙間 = 0」。（修正前のスクリーンショットでも、「解除する」ボタンの直下に緑の完了の表示が接していた）
- 原因: `.panel p { margin: 0 0 8px }`（詳細度が高い）が、`.form-success`・`.form-error` の余白（`margin: 8px 0`）を上書きし、さらに `.form-actions` に下の余白がなく、ボタンの直下に、完了・エラー・案内文が接していた。
- 修正: `src/frontend/styles/management.css` に `.push-settings-page .form-actions { margin-bottom: 12px; }` を追加（SC-15 の範囲に限定。共通の CSS・他の画面は変更していない）。修正後、12件とも成功。

### 3.2 長い値・狭い画面の確認結果

- SC-15 は、固定の文言・状態・ボタンだけを表示し、**購読の端末名（宛先）は、画面に表示しない**（一覧もない）。長い値の影響を受ける箇所は、(a) 案内文（許可なしの案内が最長）、(b) 購読の宛先の最大長（2000文字。画面外へ送るだけ）の 2 点。
- (a) 375px で 3 行に折り返し、枠・画面からはみ出さないこと、(b) 2000文字の宛先で有効化・配信・解除できること、2001文字ではエラー（「入力内容に誤りがあります」）を示し、無効のままであることを、1280・768・375px で確認した。768px・375px とも、横スクロールなし・操作ボタン（「有効にする」「解除する」）は最初の画面内にあり、届く。
- ヘッダーのメニュー（共通部品）は、768px で「通知の設定」が 2 行目に回り込む。これは共通のメニューの折り返しで、はみ出し・重なりはないため、変更していない。

1. **【確認が必要】複数の購読のうち、一部だけ配信に失敗した場合（UC-10 のレポートからの申し送り）**。`notification-service.ts:180-232` は、通知ごとに Web Push の配信状態を 1 つだけ持ち（`deliveries` の `WEB_PUSH`）、購読ごとには持たない。このため、購読が複数あり、一部だけ配信に失敗すると、通知全体が `FAILURE` となり、次の JB-04 の再送で、**すでに届いた購読にも再度配信される**（重複して届く）。仕様（use-cases.md UC-23・UC-24、functional-specification.md 3.15・5章 JB-04・6章、FR-7.2・FR-7.3・FR-7.7、dev_spec.md 4章 No.19、data-model.md の Delivery「通知、手段、結果、試行回数、日時」）には、再送の単位（通知ごとか、購読ごとか）の定めがない（FR-7.7 は「再送の方法 TODO」）。そのため、**勝手に決めず、実装・テストを変えていない**。選択肢は、(A) 現状（通知ごと。重複あり）を暫定仕様として dev_spec.md 4章に記載する、(B) 配信の状態を購読ごとに持ち、失敗した購読だけ再送する（Delivery に購読の識別子を加える。データモデルの変更を伴う）。ユーザーの判断を求める。
2. dev_spec.md 4章 No.19 は「購読者全員へ配信」とあり、**利用者を区別せず、全員の有効な購読へ配信する**（UC-23 の補足の「利用者ごとの設定か」は TODO）。実装はこのとおり。食い違いではないが、「利用者ごとに受け取る通知を変える」要件が出た場合は、変更が必要。

4. `DELETE /push-subscription` は、宛先がなければ、利用者のすべての購読を解除する（dev_spec.md 4章の記載どおり）。画面は、この端末が購読している場合にだけ「解除する」を出すため、通常は宛先付きで呼ぶ。購読の確認と解除の間に、ブラウザ側の購読が失われた場合のみ、他の端末の購読もまとめて解除される（レアケース。仕様どおりで、変更していない）。
5. 購読の宛先が 2000 文字を超える場合は、エラー表示が「入力内容に誤りがあります」になり、原因（宛先が長い）が分からない。実際の Push サービスの宛先は、この長さに届かない（数百文字）ため、変更していない。
