## 3. 不足の有無と判断

### 3.1 実装

- 基本フロー 1〜3 と、代替フロー、事後条件に必要な、画面・API・ユースケース・保存・記録は、すべてそろっている。取り込みの日時・結果・ファイル数・取得件数・読み取れなかった数・エラー内容と、連携の結果（成功・失敗・保留）・件数・内容・キューの 4 状態の件数を表示する。
- 不具合は、見つからなかった。**本体コードは変更していない**。
- 以下は、仕様に定めがない（use-cases.md の TODO）ため、現在の実装を、そのまま受け入れた事項（5 章）。ログの並べ替え操作（新しい順の固定）、再試行の回数（記録するが、画面に表示しない）、ログの保存期間。

### 3.2 テスト

- 基本フロー・代替フローの各手順は、E2E が、画面の操作と表示で、通している（2 章。テスト名でなく、コードで確認した）。
- 不足と判断して、追加したテストは次のとおり。期待値の書き換え・削除・スキップは、していない。

## 5. docs とコードの食い違い・確認が必要な事項

勝手に直していない。確認が必要なものを列挙する。

1. **ログの絞り込み・並べ替え（use-cases.md UC-16 補足の TODO）**: 実装は、取り込み元での絞り込み（すべて・ロボット・環境センサー）と、新しい順の固定（並べ替えの操作なし）。結果（成功・失敗）や期間での絞り込みはない。要件にないため、現状のままとしたが、必要かを確認したい。
2. **再試行の方法・回数（use-cases.md UC-08 の代替フロー・UC-16 関連の TODO）**: 取り込みのログは、再試行の回数（`attempts`）を記録するが、画面には出さない。画面に出すか、確認が必要。
3. **失敗・保留した連携データの再送・遅延連携（use-cases.md UC-16 補足、Q-005）**: 実装は、dev_spec.md 4.1 No.18 の暫定仕様どおり、復旧後に、保留・失敗の項目を、積んだ順にすべて送る。使うべき方針が確定していない。
4. **アクター（use-cases.md UC-16「運用者を区別するか」、Q-017）**: 実装は、ログインしていれば、閲覧者を含む誰でも、取り込み・連携の状況を参照できる（機能仕様書 4.2 の「要ログイン」と一致）。運用者・管理者を区別する場合は、権限の指定を追加する。
5. **ログの保存期間・件数の上限**: 取り込みのログ・連携の記録を、いつまで保存するか、docs に定めがない（ローカルは、上限なしで保存）。
6. **連携の記録の内容**: 機能仕様書 3.10 は「連携の結果の一覧（成功／失敗／保留、日時）」。実装は、これに、件数・内容と、連携キューの 4 状態の件数を加えている（FR-8.3 を満たす範囲の拡張。dev_spec.md 5 章の記載と一致）。
